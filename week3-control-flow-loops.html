دستور شرطی if و if-else

اولین ابزار تصمیم‌گیری در برنامه

چرا برنامه به شرط نیاز دارد؟

تا اینجا برنامه‌های ما خط‌به‌خط از بالا به پایین اجرا می‌شدند. یعنی هر دستور، بدون توجه به شرایط، دقیقاً یک بار اجرا می‌شد. اما برنامه‌های واقعی باید بتوانند بر اساس موقعیت تصمیم بگیرند. اگر موجودی حساب کافی بود پول برداشت کن، اگر رمز اشتباه بود خطا بده، اگر سن کاربر کمتر از ۱۸ سال بود اجازه ثبت‌نام نده. به این توانایی، تصمیم‌گیری می‌گوییم و ابزار آن در جاوا، دستور if است.

ساختار if ساده

ساده‌ترین شکل تصمیم‌گیری. اگر شرط درست باشد، بدنه اجرا می‌شود؛ اگر غلط باشد، بدنه کاملاً نادیده گرفته می‌شود و اجرا از خط بعدی ادامه می‌یابد.

Java 
if (condition) {
    // runs only when the condition is true
}
Java 
int score = 15;

if (score >= 10) {
    System.out.println("Passed");
}
System.out.println("Program continues...");
نکته مهم درباره شرط شرط داخل پرانتز باید حتماً یک عبارت boolean باشد؛ یعنی چیزی که نتیجه‌اش true یا false است. برخلاف زبان‌هایی مثل C که عدد صفر را معادل غلط و بقیه اعداد را معادل درست می‌دانند، در جاوا نوشتن if (1) خطای کامپایل می‌دهد. شرط باید دقیقاً از نوع boolean باشد.

ساختار if-else دوطرفه

وقتی دو مسیر ممکن داریم و در هر حالت دقیقاً یکی از آن‌ها باید اجرا شود، از if-else استفاده می‌کنیم. بخش else یعنی «هر چیزی که شرط if نبود».

Java 
if (condition) {
    // path A: condition is true
} else {
    // path B: condition is false
}
Java 
int number = 7;

if (number % 2 == 0) {
    System.out.println("Even");
} else {
    System.out.println("Odd");
}

دو اشتباه رایج

اشتباه ۱: سمی‌کالن اضافه بعد از پرانتز if اگر بعد از پرانتز شرط یک ; بگذارید، دستور if همان‌جا تمام می‌شود و بلوک بعدی مستقل از شرط اجرا می‌شود. این کار باعث می‌شود شرط شما هیچ اثری نداشته باشد و همیشه دستور داخل بلوک اجرا شود. هرگز بعد از پرانتز if سمی‌کالن نگذارید.
اشتباه ۲: استفاده از = به‌جای == عملگر = برای انتساب مقدار است و == برای مقایسه. اگر در شرط بنویسید if (x = 5)، کامپایلر خطا می‌دهد چون نتیجه انتساب از نوع متغیر است، نه boolean. همیشه در شرط از == استفاده کنید.
همیشه از آکولاد استفاده کنید برای یک خط دستور، آکولاد اختیاری است. اما استاندارد حرفه‌ای جاوا این است که همیشه از { } استفاده کنید. این کار جلوی باگ‌های عجیب در ویرایش‌های بعدی کد را می‌گیرد. مثلاً اگر بعداً بخواهید یک خط دیگر به بدنه اضافه کنید، بدون آکولاد آن خط بیرون از شرط قرار می‌گیرد و برنامه رفتار اشتباه پیدا می‌کند.

مثال‌های کاربردی

Java — بررسی سن 
int age = 20;

if (age >= 18) {
    System.out.println("You can register");
} else {
    System.out.println("Must be at least 18");
}
Java — بررسی صفر 
int number = 0;

if (number != 0) {
    System.out.println(100 / number);
} else {
    System.out.println("Cannot divide by zero");
}
Java — بررسی رمز عبور 
String password = "1234";

if (password.equals("1234")) {
    System.out.println("Access granted");
} else {
    System.out.println("Wrong password");
}
مقایسه رشته‌ها با equals، نه == برای مقایسه محتوای رشته‌ها از equals استفاده کنید، نه ==. در هفته چهارم به تفصیل توضیح داده می‌شود که چرا این دو متفاوت هستند، اما فعلاً فقط این را به خاطر بسپارید: هر وقت می‌خواهید دو رشته را از نظر محتوا مقایسه کنید، از equals استفاده کنید.
۲

ساختار نردبانی else-if

وقتی بیش از دو حالت ممکن داریم

چرا به else-if نیاز داریم؟

فرض کنید می‌خواهید برای نمره یک دانشجو سطح تعیین کنید: بالای ۱۷ عالی، بین ۱۴ تا ۱۷ خوب، بین ۱۰ تا ۱۴ متوسط و پایین‌تر از ۱۰ مردود. با یک if-else ساده فقط دو حالت را می‌شود پوشش داد. برای بیش از دو حالت، از ساختار نردبانی else-if استفاده می‌کنیم.

ساختار کلی

در این ساختار، کامپیوتر از بالا شروع می‌کند و به محض رسیدن به اولین شرط درست، بدنه آن را اجرا کرده و از کل نردبان خارج می‌شود. شرط‌های بعدی حتی بررسی نمی‌شوند.

Java 
if (condition1) {
    // case 1
} else if (condition2) {
    // case 2
} else if (condition3) {
    // case 3
} else {
    // none of the above
}
Java — تعیین سطح نمره 
double grade = 16.5;

if (grade >= 17) {
    System.out.println("A");
} else if (grade >= 14) {
    System.out.println("B");
} else if (grade >= 10) {
    System.out.println("C");
} else {
    System.out.println("F");
}

ترتیب شرط‌ها اهمیت حیاتی دارد

اگر در مثال بالا شرط grade >= 10 را قبل از grade >= 17 بنویسید، نمره ۱۸ هم در شرط اول درست است و هم هرگز به شاخه «عالی» نمی‌رسد. همیشه شرط‌های محدودتر را بالاتر بنویسید و شرط‌های کلی‌تر را پایین‌تر.

ترتیب شرط‌ها را اشتباه نگیرید ساختار else-if یک زنجیره است و به محض رسیدن به اولین شرط درست، از آن خارج می‌شود. اگر شرط کلی‌تر را بالاتر بنویسید، شرط‌های بعدی هرگز شانس اجرا پیدا نمی‌کنند. همیشه از محدودترین به کلی‌ترین حرکت کنید.

else-if را با ifهای مستقل اشتباه نگیرید

اگر به‌جای else if، چند if پشت‌سرهم بنویسید، همه شرط‌ها جداگانه بررسی می‌شوند. این کار ممکن است باعث شود چند پیام متناقض چاپ شود. مثلاً اگر برای نمره ۱۸، هم شرط «قبول» (نمره ≥ ۱۰) و هم شرط «عالی» (نمره ≥ ۱۷) را با ifهای مستقل بنویسید، هر دو پیام چاپ می‌شوند که منطقی نیست.

Java — اشتباه رایج 
int score = 18;

// Wrong: both messages will print
if (score >= 10) System.out.println("Passed");
if (score >= 17) System.out.println("Excellent");

// Correct: only one message will print
if (score >= 17) {
    System.out.println("Excellent");
} else if (score >= 10) {
    System.out.println("Passed");
}

مثال کاربردی: تخفیف پلکانی فروشگاه

فرض کنید یک فروشگاه برای خریدهای بالاتر از یک مبلغ مشخص، تخفیف در نظر می‌گیرد. این سناریو دقیقاً ساختار نردبانی می‌خواهد.

Java 
double amount = 750000;
double finalAmount;

if (amount >= 1000000) {
    finalAmount = amount * 0.8;   // 20% off
} else if (amount >= 500000) {
    finalAmount = amount * 0.9;   // 10% off
} else {
    finalAmount = amount;             // no discount
}

System.out.println("Final amount: " + finalAmount);
توصیه هر وقت بیش از دو حالت دارید، اول با خودتان بنویسید کدام شرط «محدودتر» است و کدام «کلی‌تر». از محدودترین شروع کنید و به کلی‌ترین برسید. این کار جلوی بسیاری از باگ‌های منطقی را می‌گیرد.
۳

شروط تودرتو

فیلترهای چندمرحله‌ای روی داده‌ها

شروط تودرتو چیست؟

وقتی یک if یا else داخل بدنه یک if دیگر قرار می‌گیرد، به آن شرط تودرتو می‌گوییم. نکته کلیدی این است که شرط داخلی فقط زمانی بررسی می‌شود که شرط بیرونی درست باشد. این ساختار مثل فیلترهای پشت‌سرهم عمل می‌کند: اول مجوز ورود، بعد بررسی مدارک.

مثال: احراز هویت دومرحله‌ای

فرض کنید می‌خواهید برای صدور سیم‌کارت، دو شرط را بررسی کنید: اول اینکه سن کاربر بالای ۱۸ سال باشد، دوم اینکه کارت ملی همراه داشته باشد. با شرط تودرتو، ترتیب این دو بررسی مشخص می‌شود.

Java 
int age = 21;
boolean hasNationalCard = true;

if (age >= 18) {
    // inner condition is checked only if age >= 18
    if (hasNationalCard) {
        System.out.println("Registration complete.");
    } else {
        System.out.println("National card required.");
    }
} else {
    System.out.println("Must be at least 18.");
}

ریشه منطقی شرط تودرتو

شرط تودرتو در واقع همان ترکیب دو شرط با AND منطقی است، اما در برخی موارد خواناتر است. اگر بخواهیم همان مثال بالا را با && بنویسیم، می‌شود if (age >= 18 && hasNationalCard). تفاوت این است که در ساختار تودرتو می‌توانید برای هر شرط پیام خطای متفاوتی بدهید، اما در && فقط یک پیام کلی می‌توانید چاپ کنید.

کِی از شرط تودرتو استفاده کنیم؟ وقتی می‌خواهید برای هر فیلتر، پیام خطای متفاوتی بدهید. مثلاً اگر سن کم بود بگویید «سن شما کافی نیست» و اگر کارت ملی نبود بگویید «لطفاً کارت ملی همراه داشته باشید». با && فقط می‌توانید یک پیام کلی مثل «شرایط احراز هویت کامل نیست» بدهید. انتخاب روش درست، به کیفیت تجربه کاربری برنامه برمی‌گردد.

مثال: تصمیم فروشگاه بر اساس موجودی و بودجه

Java 
int stock = 5;
int budget = 100000;
int price = 45000;

if (stock > 0) {
    if (budget >= price) {
        System.out.println("Order placed successfully");
    } else {
        System.out.println("Insufficient budget");
    }
} else {
    System.out.println("Product out of stock");
}

نکات مهم درباره شرط تودرتو

  • تو رفتگی (indent): هر سطح تودرتو را با فاصله مناسب مشخص کنید تا سلسله‌مراتب شرط‌ها دیده شود.
  • تعداد لایه‌ها: بیش از دو یا سه سطح تودرتو، خوانایی کد را بسیار پایین می‌آورد. اگر نیاز به لایه‌های بیشتر شد، احتمالاً باید منطق را با متدها یا ساختارهای دیگر بشکنید.
  • else به کدام if برمی‌گردد؟ در زبان‌های خانواده C، هر else به نزدیک‌ترین if قبل از خودش تعلق دارد. برای جلوگیری از ابهام، همیشه از آکولاد استفاده کنید.
دام else معلق اگر آکولادها را حذف کنید، ممکن است else به if اشتباهی وصل شود. همیشه از آکولاد استفاده کنید تا ساختار دقیقاً همان‌طور که قصد دارید اجرا شود.
۴

ساختار switch

مقایسه یک متغیر با چند مقدار ثابت

کِی از switch استفاده کنیم؟

وقتی می‌خواهید یک متغیر واحد را با چند مقدار ثابت مقایسه کنید (مثل منوی انتخاب)، switch خواناتر و مرتب‌تر از زنجیره طولانی if-else است. به جای نوشتن چند if پشت‌سرهم، یک ساختار تمیز و شبیه به منو دارید.

ساختار سنتی switch

Java 
switch (variable) {
    case value1:
        // code
        break;
    case value2:
        // code
        break;
    default:
        // runs when no case matches
}
Java — منوی ساده 
int choice = 2;

switch (choice) {
    case 1:
        System.out.println("Buy credit");
        break;
    case 2:
        System.out.println("Check balance");
        break;
    case 3:
        System.out.println("Internet packages");
        break;
    default:
        System.out.println("Invalid choice");
}

قوانین و محدودیت‌ها

  • انواع مجاز: byte، short، char، int، String (از جاوا ۷ به بعد) و enum. انواع long، float، double و boolean مجاز نیستند.
  • فقط تساوی: در case فقط مقدار ثابت قابل مقایسه است. نمی‌توانید بازه بنویسید (مثل case x > 10:) یا شرط بولی بگذارید.
  • break: پس از اجرای هر case، دستور break از switch خارج می‌شود. اگر فراموش شود، اجرا به caseهای بعدی «نفوذ» می‌کند.
  • default: اختیاری است اما توصیه می‌شود. برای حالتی است که هیچ case مطابقت نداشته باشد.
پدیده Fall-through (نفوذ) اگر break را فراموش کنید، پس از اجرای case جاری، caseهای بعدی هم پشت‌سرهم اجرا می‌شوند. این رفتار در ابتدا عجیب به نظر می‌رسد، اما یک قاعده مشخص در جاواست. برای جلوگیری از آن، همیشه پس از هر case دستور break را بنویسید.
Java — نمونه fall-through 
int day = 1;

switch (day) {
    case 1:
        System.out.println("Saturday");   // prints
        // missing break → falls through
    case 2:
        System.out.println("Sunday");     // also prints!
        break;
    default:
        System.out.println("Invalid");
}

نفوذ عمدی: گروه‌بندی caseها

گاهی نبودن break عمدی است. اگر بخواهید چند مقدار، یک کد مشترک را اجرا کنند، می‌توانید caseها را خالی پشت هم بگذارید. این تکنیک رایج است و در کد حرفه‌ای زیاد دیده می‌شود.

Java 
switch (day) {
    case 5:
    case 6:
        System.out.println("Weekend");
        break;
    default:
        System.out.println("Workday");
}

switch مدرن (از جاوا ۱۴ به بعد)

از نسخه ۱۴ جاوا، سینتکس جدیدی برای switch معرفی شد که مشکلات نسخه سنتی را حل می‌کند. در این نسخه، هر case با -> نوشته می‌شود، هیچ نفوذی بین caseها وجود ندارد و نیازی به break نیست.

Java — switch مدرن 
int choice = 2;

switch (choice) {
    case 1 -> System.out.println("Buy credit");
    case 2 -> System.out.println("Check balance");
    case 3 -> System.out.println("Internet packages");
    default -> System.out.println("Invalid choice");
}

چند مقدار در یک case

در نسخه مدرن می‌توان چند مقدار را با کاما در یک case گروه کرد. این کار بسیار خواناتر از نوشتن چند case خالی پشت سر هم است.

Java — گروه‌بندی caseها 
int month = 2;

switch (month) {
    case 1, 2, 3 -> System.out.println("Spring");
    case 4, 5, 6 -> System.out.println("Summer");
    case 7, 8, 9 -> System.out.println("Autumn");
    case 10, 11, 12 -> System.out.println("Winter");
    default -> System.out.println("Invalid month");
}

switch به‌عنوان یک عبارت (Switch Expression)

بزرگ‌ترین مزیت نسخه مدرن این است که switch می‌تواند خودش یک مقدار تولید کند و آن را مستقیماً به یک متغیر نسبت دهید. دیگر نیازی به متغیر موقت و break نیست.

Java — switch به‌عنوان عبارت 
int month = 2;

String season = switch (month) {
    case 1, 2, 3 -> "Spring";
    case 4, 5, 6 -> "Summer";
    case 7, 8, 9 -> "Autumn";
    case 10, 11, 12 -> "Winter";
    default -> "Invalid month";
};

System.out.println(season);   // Spring

پشتیبانی از بازهداردندارد

تکرار دستورات تا زمانی که شرط برقرار است

چرا به حلقه نیاز داریم؟

تصور کنید باید عبارت «سلام» را ۱۰۰ بار چاپ کنید. نوشتن ۱۰۰ خط دستور، نه عملی است و نه خوانا. کامپیوترها برای همین کارهای تکراری ساخته شده‌اند. به ساختاری که یک تکه کد را بارها تکرار می‌کند، حلقه می‌گوییم. ساده‌ترین حلقه، while است.

ساختار while

حلقه while ابتدا شرط را بررسی می‌کند. اگر درست بود، بدنه را اجرا می‌کند. بعد دوباره به شرط برمی‌گردد و همین کار را تکرار می‌کند تا زمانی که شرط غلط شود.

Java 
while (condition) {
    // repeated code
    // update the counter so the loop can finish
}
Java 
int i = 1;

while (i <= 5) {
    System.out.println(i);
    i++;   // don't forget this
}
حلقه بی‌نهایت اگر متغیر شرط را داخل حلقه به‌روزرسانی نکنید (مثلاً i++ را فراموش کنید)، شرط همیشه درست می‌ماند و برنامه قفل می‌شود. هرگز بعد از پرانتز while سمی‌کالن نگذارید، چون در آن صورت حلقه روی یک دستور خالی اجرا می‌شود و بدنه بعدی بی‌ربط خواهد بود.

مثال‌های کاربردی while

Java — شمارش معکوس 
int count = 5;

while (count > 0) {
    System.out.println(count);
    count--;
}
System.out.println("Liftoff!");
Java — جمع اعداد تا صفر 
Scanner sc = new Scanner(System.in);
int sum = 0;
int number = -1;

while (number != 0) {
    System.out.print("Enter a number (0 to stop): ");
    number = sc.nextInt();
    sum += number;
}

System.out.println("Sum = " + sum);

ویژگی کلیدی while

چون شرط قبل از ورود به حلقه بررسی می‌شود، اگر از همان ابتدا غلط باشد، بدنه هیچ‌وقت اجرا نمی‌شود. یعنی حلقه while ممکن است صفر بار اجرا شود. این ویژگی برای مواردی مناسب است که «شاید اصلاً نیازی به تکرار نباشد».

حلقه do-while

گاهی می‌خواهیم بدنه حلقه حداقل یک بار اجرا شود، حتی اگر شرط از همان ابتدا غلط باشد. مثلاً در یک منو، کاربر باید حتماً یک بار منو را ببیند، حتی اگر بخواهد بلافاصله خارج شود. برای این حالت از do-while استفاده می‌کنیم.

Java 
do {
    // runs at least once
} while (condition);   // semicolon is required here

مقایسه while و do-while

ویژگی while do-while
زمان بررسی شرطقبل از هر دوربعد از هر دور
حداقل تعداد اجرا۰ بار۱ بار
سمی‌کالن انتهایینداردالزامی است
کاربرد رایجتکرار تا برقراری شرطمنو، اعتبارسنجی ورودی

مثال: منوی تعاملی

Java — منو با do-while 
Scanner sc = new Scanner(System.in);
int choice;

do {
    System.out.println("1) Show balance");
    System.out.println("2) Deposit");
    System.out.println("0) Exit");
    System.out.print("Choice: ");
    choice = sc.nextInt();

    switch (choice) {
        case 1 -> System.out.println("Balance: ...");
        case 2 -> System.out.println("Deposited.");
        case 0 -> System.out.println("Goodbye!");
        default -> System.out.println("Invalid option");
    }
} while (choice != 0);

مثال: اعتبارسنجی ورودی

Java — دریافت سن معتبر 
Scanner sc = new Scanner(System.in);
int age;

do {
    System.out.print("Age (1 to 100): ");
    age = sc.nextInt();
} while (age < 1 || age > 100);
انتخاب درست بین while و do-while اگر شک دارید که «شاید اصلاً نیازی به تکرار نباشد»، از while استفاده کنید. اگر «حداقل یک بار باید اجرا شود» (مثل منو یا اعتبارسنجی اولیه)، از do-while استفاده کنید. انتخاب درست، خوانایی کد را بیشتر می‌کند و به خواننده می‌گوید قصد برنامه‌نویس چه بوده است.

حلقه for و حلقه‌های تودرتو

وقتی تعداد تکرارها از قبل مشخص است

ساختار for

اگر از قبل بدانید کاری دقیقاً چند بار تکرار می‌شود، for جمع‌وجورترین انتخاب است. در آن، سه بخش «شروع»، «شرط» و «گام» در یک خط نوشته می‌شوند و کد شما بسیار خواناتر می‌شود.

Java 
for (initialization; condition; update) {
    // repeated code
}
  • شروع: متغیر شمارنده یک بار ساخته می‌شود (مثلاً int i = 1).
  • شرط: قبل از هر دور بررسی می‌شود (مثلاً i <= 5).
  • گام: بعد از هر دور اجرا می‌شود (مثلاً i++).
Java — شمارش ۱ تا ۵ 
for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

انعطاف‌های رایج

Java — شمارش معکوس 
for (int i = 5; i >= 1; i--) {
    System.out.println(i);
}
Java — گام دو تا دو تا 
for (int i = 2; i <= 20; i += 2) {
    System.out.println(i);
}

مثال: جمع اعداد ۱ تا ۱۰

Java 
int sum = 0;

for (int i = 1; i <= 10; i++) {
    sum += i;
}

System.out.println("Sum = " + sum);   // 55
دامنه متغیر شمارنده متغیری که در بخش شروع for تعریف می‌شود، فقط داخل همان حلقه معتبر است. بعد از پایان حلقه به آن دسترسی ندارید. اگر بعداً به مقدار نهایی آن نیاز دارید، آن را قبل از حلقه تعریف کنید.

حلقه‌های تودرتو

حلقه تودرتو یعنی یک حلقه درون حلقه دیگر. مثل عقربه‌های ساعت: به ازای هر یک دور عقربه ساعت‌شمار، عقربه دقیقه‌شمار شصت دور کامل می‌زند. به همین ترتیب، حلقه درونی برای هر تک‌تک دورهای حلقه بیرونی به‌طور کامل اجرا می‌شود. این الگو برای رسم جدول و شکل‌های ستاره‌ای کاربرد دارد.

مثال: مستطیل ستاره‌ای ۳ در ۵

Java 
for (int row = 1; row <= 3; row++) {

    for (int col = 1; col <= 5; col++) {
        System.out.print("* ");
    }
    System.out.println();   // move to the next line
}

خروجی این کد به این شکل است:

Output 
* * * * *
* * * * *
* * * * *

مثال: مثلث قائم‌الزاویه

Java 
for (int i = 1; i <= 4; i++) {
    for (int j = 1; j <= i; j++) {
        System.out.print("* ");
    }
    System.out.println();
}

خروجی این کد مثلثی است که در هر سطر، یک ستاره بیشتر از سطر قبل دارد:

Output 
*
* *
* * *
* * * *
تفاوت print و println برای چاپ ستون‌های یک سطر از System.out.print استفاده کنید (بدون رفتن به خط بعد). در پایان هر سطر با System.out.println() به خط بعد بروید. اشتباه در این دو، شکل خروجی را کاملاً خراب می‌کند.
break فقط از حلقه درونی خارج می‌شود اگر داخل حلقه درونی break بزنید، فقط همان حلقه درونی متوقف می‌شود و حلقه بیرونی به دور بعدی خود ادامه می‌دهد. برای خروج از چند سطح، به تکنیک‌های پیشرفته‌تر مثل برچسب (label) نیاز دارید که در سطح مقدماتی ضروری نیست.

کنترل رفتار حلقه با break و continue

ترمز و پرش در وسط حلقه

چرا به break و continue نیاز داریم؟

گاهی لازم است بدون منتظر ماندن برای پایان طبیعی حلقه، رفتار آن را کنترل کنیم. دو دستور ساده برای این کار وجود دارد: break و continue. این دو دستور به شما اجازه می‌دهند حلقه را دقیقاً همان‌طور که می‌خواهید هدایت کنید.

  • break (خروج فوری): حلقه را همان لحظه تمام می‌کند و اجرا به اولین خط بعد از حلقه می‌رود.
  • continue (رد کردن دور فعلی): بقیه خطوط دور جاری را نادیده می‌گیرد و فوراً به دور بعدی می‌رود.

مثال: break برای پیدا کردن یک عدد

Java 
for (int i = 1; i <= 10; i++) {
    if (i == 7) {
        break;   // stop the loop entirely
    }
    System.out.println(i);   // prints 1 to 6
}

مثال: continue برای رد کردن یک عدد

Java 
for (int i = 1; i <= 5; i++) {
    if (i == 3) {
        continue;   // skip this iteration only
    }
    System.out.println(i);   // prints 1, 2, 4, 5
}

الگوی حلقه بی‌نهایت با شرط خروج

یکی از الگوهای رایج، استفاده از while (true) به‌همراه یک شرط داخلی است که با break از حلقه خارج می‌شود. این الگو زمانی مفید است که تعداد دفعات تکرار از قبل مشخص نیست و بر اساس ورودی کاربر تعیین می‌شود.

Java 
Scanner sc = new Scanner(System.in);

while (true) {
    System.out.print("Enter a number (0 to exit): ");
    int n = sc.nextInt();

    if (n == 0) {
        break;   // leave the infinite loop
    }

    System.out.println("Square: " + (n * n));
}
تله continue در while اگر continue را قبل از به‌روزرسانی شمارنده بزنید، حلقه ممکن است هرگز پایان نیابد. مثلاً در حلقه‌ای که i++ در انتهای بدنه است، اگر پیش از i++ از continue استفاده کنید، i هیچ‌وقت زیاد نمی‌شود و شرط همیشه درست می‌ماند. در حلقه for این مشکل کمتر پیش می‌آید، چون بخش گام (i++) حتی با continue هم اجرا می‌شود.

مقایسه break و continue

دستور تأثیر کِی استفاده کنیم
break حلقه را کاملاً متوقف می‌کند و به خط بعد از حلقه می‌رود وقتی «دیگر هیچ دوری لازم نیست»؛ مثلاً پیدا شدن مقدار جستجو شده
continue فقط دور فعلی را رد می‌کند و به دور بعدی می‌رود وقتی «فقط این دور را نادیده بگیر»؛ مثلاً رد کردن اعداد منفی در محاسبه

مثال کاربردی: جمع نمرات بدون احتساب نمرات منفی

Java 
Scanner sc = new Scanner(System.in);
double total = 0;

for (int i = 1; i <= 4; i++) {
    System.out.print("Grade for student " + i + ": ");
    double score = sc.nextDouble();

    if (score < 0) {
        System.out.println("Negative score ignored.");
        continue;
    }

    total += score;
}

System.out.println("Total: " + total);
قاعده انتخاب «این دور را نادیده بگیر و برو بعدی» ← continue. «دیگر هیچ دوری اجرا نشود» ← break. اگر این دو جمله را به خاطر بسپارید، همیشه انتخاب درستی خواهید داشت.

تمرین‌ها و راهنما

دو پروژه کلاسی و دو تمرین منزل برای تثبیت مطالب

پروژه کلاسی ۱

شبیه‌سازی ورود به سیستم بانکی

برنامه‌ای بنویسید که از کاربر رمز عبور بگیرد. کاربر سه شانس برای وارد کردن رمز صحیح دارد. اگر هر سه بار اشتباه وارد کرد، حساب قفل می‌شود و پیام مناسب نمایش داده می‌شود. اگر رمز درست بود، بلافاصله پیام خوش‌آمدگویی نمایش داده شود و برنامه پایان یابد.

منطق کلی
  1. رمز صحیح از قبل در برنامه مشخص است (مثلاً 1234).
  2. کاربر حداکثر سه بار می‌تواند رمز وارد کند.
  3. اگر رمز درست بود، پیام موفقیت و خروج از حلقه.
  4. اگر سه بار اشتباه شد، پیام قفل حساب.
راهنمای گام‌به‌گام
  1. ۱
    یک شیء Scanner بسازید و یک متغیر ثابت برای رمز صحیح تعریف کنید.
  2. ۲
    یک متغیر boolean loggedIn = false تعریف کنید تا وضعیت ورود موفق را ثبت کند.
  3. ۳
    یک حلقه for بنویسید که حداکثر سه بار اجرا شود (از ۱ تا ۳).
  4. ۴
    در هر دور، رمز را از کاربر بگیرید و با رمز صحیح مقایسه کنید. اگر رمز از نوع int است، با == مقایسه کنید. اگر String است، با equals.
  5. ۵
    اگر رمز درست بود، loggedIn = true کنید، پیام موفقیت چاپ کنید و با break از حلقه خارج شوید.
  6. ۶
    اگر رمز اشتباه بود، پیام خطا و تعداد شانس باقی‌مانده را چاپ کنید.
  7. ۷
    بعد از پایان حلقه، اگر loggedIn هنوز false است، پیام قفل حساب را چاپ کنید.
اشتباهات رایج و خطاهای احتمالی
  • مقایسه رشته‌ها با ==: اگر رمز را از نوع String گرفتید، حتماً از equals استفاده کنید. == آدرس حافظه را مقایسه می‌کند و ممکن است نتیجه اشتباه بدهد.
  • فراموش کردن break بعد از ورود موفق: اگر بعد از ورود موفق break نزنید، حلقه ادامه می‌یابد و از کاربر دوباره رمز می‌خواهد. این رفتار با منطق برنامه در تضاد است.
  • شمارش اشتباه شانس‌ها: اگر حلقه را از ۰ تا ۲ بنویسید یا شرط را < به‌جای <= بگذارید، تعداد شانس‌ها درست نخواهد بود. دقیقاً روی سه بار اجرا تست کنید.
  • چاپ پیام قفل حساب حتی وقتی کاربر موفق شده: اگر متغیر loggedIn را بعد از break بررسی نکنید، ممکن است پیام قفل هم چاپ شود. ترتیب منطق را دقیق بررسی کنید.
  • خطای ورودی در nextInt: اگر کاربر به‌جای عدد، حرف وارد کند، برنامه با خطای ورودی متوقف می‌شود. برای این تمرین، ورودی صحیح را فرض کنید.
پروژه کلاسی ۲

بازی حدس عدد

برنامه یک عدد تصادفی بین ۱ تا ۱۰۰ انتخاب می‌کند. کاربر باید با راهنمایی‌های «بزرگ‌تر است» یا «کوچک‌تر است» آن را حدس بزند. برنامه تعداد شانس‌های مشخصی (مثلاً هفت بار) به کاربر می‌دهد. اگر کاربر در این فرصت‌ها عدد را پیدا کرد، برنده می‌شود. در غیر این صورت، برنامه عدد صحیح را اعلام می‌کند.

منطق کلی
  1. برنامه یک عدد تصادفی بین ۱ تا ۱۰۰ تولید می‌کند.
  2. کاربر هفت شانس دارد.
  3. در هر شانس، اگر حدس درست بود، برنده می‌شود.
  4. اگر حدس کمتر بود، راهنمایی «بزرگ‌تر» و اگر بیشتر بود، «کوچک‌تر».
  5. اگر شانس‌ها تمام شد، عدد صحیح اعلام می‌شود.
راهنمای گام‌به‌گام
  1. ۱
    برای تولید عدد تصادفی، از (int)(Math.random() * 100) + 1 استفاده کنید. این عبارت یک عدد بین ۱ تا ۱۰۰ می‌دهد.
  2. ۲
    یک متغیر boolean won = false تعریف کنید تا وضعیت برد را ثبت کند.
  3. ۳
    یک حلقه for بنویسید که هفت بار اجرا شود (از ۱ تا ۷).
  4. ۴
    در هر دور، شماره شانس و عدد حدس را از کاربر بگیرید.
  5. ۵
    اگر حدس برابر عدد مخفی بود، پیام برد و won = true و break.
  6. ۶
    اگر حدس کمتر بود، پیام «عدد بزرگ‌تری حدس بزن».
  7. ۷
    اگر حدس بیشتر بود، پیام «عدد کوچک‌تری حدس بزن».
  8. ۸
    بعد از حلقه، اگر won هنوز false است، پیام باخت و عدد صحیح را چاپ کنید.
اشتباهات رایج و خطاهای احتمالی
  • تولید عدد تصادفی خارج از بازه: اگر بنویسید (int)(Math.random() * 100)، عدد می‌تواند صفر شود. برای شروع از ۱، حتماً + 1 را اضافه کنید.
  • برعکس بودن راهنمایی‌ها: اگر حدس کوچک‌تر از عدد مخفی بود، باید بگویید «عدد بزرگ‌تر»؛ نه برعکس. این رایج‌ترین اشتباه در این بازی است. با یک عدد نمونه (مثلاً ۵۰) مسیر را ذهنی بررسی کنید.
  • فراموش کردن break بعد از برد: اگر بعد از برد حلقه را متوقف نکنید، بازی ادامه می‌یابد و ممکن است پیام‌های بیشتری چاپ شود که منطقی نیست.
  • چاپ نکردن عدد صحیح در صورت باخت: اگر کاربر نتوانست حدس بزند، باید عدد صحیح اعلام شود تا کاربر از نتیجه مطلع شود. این جزو تجربه بازیکن است.
  • محدوده نامشخص: بهتر است در ابتدای هر دور، بازه فعلی (مثلاً «بین ۳۰ تا ۵۰») را نمایش دهید تا بازی جذاب‌تر و آسان‌تر شود.
تمرین منزل ۱

نمایش جدول ضرب یک عدد

برنامه‌ای بنویسید که یک عدد صحیح از کاربر دریافت کند و جدول ضرب آن عدد را از ۱ تا ۱۰ در خروجی نمایش دهد. خروجی باید مرتب و هم‌تراز باشد. اگر کاربر عدد ۰ وارد کرد، برنامه با پیام مناسب خاتمه یابد.

راهنمای گام‌به‌گام
  1. ۱
    یک شیء Scanner بسازید و عدد را با nextInt دریافت کنید.
  2. ۲
    اگر عدد وارد شده صفر بود، پیام مناسب چاپ کنید و با return یا پایان برنامه، ادامه ندهید.
  3. ۳
    یک حلقه for از ۱ تا ۱۰ بنویسید.
  4. ۴
    در هر دور، حاصل‌ضرب را در قالبی مثل عدد × i = نتیجه چاپ کنید.
  5. ۵
    برای هم‌ترازی، از System.out.printf استفاده کنید. مثلاً %d × %d = %d%n با عرض ثابت مثل %3d برای هر عدد.
  6. ۶
    در پایان، sc.close() را صدا بزنید.
اشتباهات رایج و خطاهای احتمالی
  • نبود هم‌ترازی در خروجی: اگر از println ساده استفاده کنید، ستون‌ها ناهماهنگ می‌شوند. با printf و عرض ثابت (مثلاً %3d)، خروجی مرتب می‌شود.
  • فراموش کردن بررسی صفر: اگر صفر را بررسی نکنید، برنامه جدول ضرب صفر را چاپ می‌کند که طبق صورت تمرین درست نیست.
  • استفاده از nextDouble به‌جای nextInt: عدد ورودی یک عدد صحیح است. اگر از nextDouble استفاده کنید، ممکن است نتیجه اعشاری شود و با جدول ضرب هماهنگ نباشد.
  • چاپ نکردن پیام مناسب برای صفر: پیام باید واضح باشد، مثلاً «جدول ضرب برای صفر تعریف نشده است».
تمرین منزل ۲

یافتن اعداد اول بین ۱ تا ۱۰۰۰

برنامه‌ای بنویسید که همه اعداد اول بین ۱ تا ۱۰۰۰ را پیدا کرده و چاپ کند. عدد اول عددی است که فقط بر ۱ و خودش بخش‌پذیر باشد. عدد ۱ اول نیست. عدد ۲ تنها عدد اول زوج است.

راهنمای گام‌به‌گام
  1. ۱
    یک حلقه for بیرونی از ۲ تا ۱۰۰۰ بنویسید (عدد ۱ اول نیست).
  2. ۲
    داخل حلقه بیرونی، یک متغیر boolean isPrime = true تعریف کنید.
  3. ۳
    یک حلقه درونی از ۲ تا ریشه دوم عدد بنویسید. شرط حلقه را می‌توانید d * d <= n بنویسید تا از Math.sqrt استفاده نکنید.
  4. ۴
    در هر دور حلقه درونی، بررسی کنید آیا عدد بر d بخش‌پذیر است. اگر بود، isPrime = false کنید و با break از حلقه درونی خارج شوید.
  5. ۵
    بعد از پایان حلقه درونی، اگر isPrime هنوز true است، عدد را چاپ کنید.
اشتباهات رایج و خطاهای احتمالی
  • تعریف isPrime بیرون از حلقه بیرونی: اگر متغیر isPrime را بیرون از حلقه بیرونی تعریف کنید، مقدار آن بین اعداد مختلف حفظ می‌شود و نتیجه اشتباه می‌شود. باید برای هر عدد، از نو مقدار بگیرد.
  • بررسی تا خود عدد: اگر حلقه درونی را تا خود عدد بزنید، برنامه برای اعداد بزرگ کند می‌شود. بررسی تا ریشه دوم کافی است و بسیار سریع‌تر است.
  • شروع حلقه درونی از ۱: اگر از ۱ شروع کنید، همه اعداد بر ۱ بخش‌پذیرند و هیچ عددی اول تشخیص داده نمی‌شود. حتماً از ۲ شروع کنید.
  • فراموش کردن break در حلقه درونی: بعد از پیدا کردن یک مقسوم‌علیه، نیازی به ادامه بررسی نیست. break سرعت برنامه را بالا می‌برد.
  • شمارش عدد ۱ به‌عنوان اول: عدد ۱ طبق تعریف، اول نیست. حلقه بیرونی باید از ۲ شروع شود.

پرسش و پاسخ

پرسش‌های پرتکرار این هفته و پاسخ روشن آن‌ها

این بخش جمع‌بندی پرسش‌هایی است که معمولاً در هفته سوم برای دانشجویان پیش می‌آید. اگر پرسشی مشابه داشتید، پاسخ آن را همین‌جا پیدا می‌کنید.

پرسش: کِی از if-else استفاده کنم و کِی از switch؟

پاسخ: اگر شرط شما شامل بازه یا ترکیب چند شرط است (مثل age >= 18 && hasId)، از if-else استفاده کنید. اگر می‌خواهید یک متغیر را با چند مقدار ثابت مقایسه کنید (مثل کد منو)، switch خواناتر است. یک قاعده سرانگشتی: وقتی بیش از سه یا چهار حالت ثابت دارید، switch انتخاب بهتری است. در نسخه مدرن جاوا، switch حتی می‌تواند مقدار برگرداند و کد شما را کوتاه‌تر کند.

پرسش: تفاوت while و do-while چیست و کدام را انتخاب کنم؟

پاسخ: while ابتدا شرط را بررسی می‌کند؛ اگر از همان ابتدا غلط باشد، بدنه هیچ‌وقت اجرا نمی‌شود. do-while ابتدا بدنه را یک بار اجرا می‌کند و بعد شرط را بررسی می‌کند؛ پس حداقل یک بار اجرا می‌شود. اگر مطمئن نیستید که آیا نیاز به تکرار هست یا نه، while انتخاب امن‌تری است. اگر می‌خواهید حتماً یک بار اجرا شود (مثل منوی برنامه)، از do-while استفاده کنید. یک نکته جزئی: در do-while، بعد از شرط باید سمی‌کالن بگذارید.

پرسش: چرا برنامه من در حلقه while قفل می‌شود؟

پاسخ: رایج‌ترین علت، فراموش کردن به‌روزرسانی شمارنده است. اگر داخل حلقه i++ یا i-- را ننویسید، شرط همیشه درست می‌ماند و حلقه هیچ‌وقت تمام نمی‌شود. علت دیگری که کمتر رایج است، نوشتن سمی‌کالن اضافه بعد از پرانتز while است؛ در این حالت حلقه روی یک دستور خالی اجرا می‌شود و شرط هم همیشه درست می‌ماند. همیشه بعد از نوشتن حلقه، یک بار ذهنی بررسی کنید: «آیا شرط در نهایت غلط می‌شود؟» اگر پاسخ منفی است، جایی اشتباه کرده‌اید.

پرسش: چرا بعد از هر case در switch باید break بنویسم؟

پاسخ: اگر break را فراموش کنید، اجرا به case بعدی «نفوذ» می‌کند. یعنی بعد از اجرای case جاری، caseهای بعدی هم پشت‌سرهم اجرا می‌شوند. این رفتار در واقع یک ویژگی زبان است، اما معمولاً باعث باگ می‌شود. اگر عمداً می‌خواهید چند case یک کد مشترک را اجرا کنند، نبودن break منطقی است؛ در غیر این صورت، همیشه break بنویسید. در نسخه مدرن جاوا (سینتکس ->)، دیگر نیازی به break نیست و این مشکل اصلاً پیش نمی‌آید.

پرسش: تفاوت break و continue در چیست؟

پاسخ: break حلقه را کاملاً متوقف می‌کند و اجرا به اولین خط بعد از حلقه می‌رود. continue فقط دور فعلی را نادیده می‌گیرد و به دور بعدی می‌رود. یک جمله ساده برای یادسپاری: «break می‌شکند، continue می‌پرد». اگر می‌خواهید حلقه دیگر ادامه پیدا نکند، break. اگر می‌خواهید یک دور خاص را نادیده بگیرید، continue. در حلقه while، مراقب باشید که continue قبل از به‌روزرسانی شمارنده نباشد، وگرنه حلقه بی‌نهایت می‌شود.

پرسش: چطور بفهمم کدام نوع حلقه را انتخاب کنم؟

پاسخ: سه سؤال از خودتان بپرسید. اول، آیا تعداد تکرارها از قبل مشخص است؟ اگر بله، for بهترین انتخاب است. دوم، آیا حداقل یک بار باید اجرا شود (مثل منو)؟ اگر بله، do-while. سوم، آیا تکرار تا زمانی که شرطی برقرار بماند (مثل گرفتن رمز درست)؟ اگر بله، while. با این سه سؤال، انتخاب درست تقریباً همیشه مشخص است. اگر شک داشتید، while یا for معمولاً گزینه‌های امنی هستند.

پرسش: آیا می‌توانم از حلقه تو در تو در حلقه تو در توی دیگری استفاده کنم؟

پاسخ: بله، از نظر فنی هیچ محدودیتی وجود ندارد. اما در عمل، بیش از سه سطح تودرتو خوانایی کد را به‌شدت پایین می‌آورد و رفع باگ را بسیار سخت می‌کند. اگر نیاز به حلقه‌های عمیق‌تر دارید، بهتر است منطق را به متدهای جداگانه بشکنید یا ساختار داده مناسب‌تری انتخاب کنید. برای تمرین‌های این دوره، دو سطح تودرتو کافی است. اگر در حال نوشتن کدی هستید که به سه سطح یا بیشتر رسیده، احتمالاً می‌توانید آن را با یک متد جداگانه ساده‌تر کنید.

پرسش: در حلقه for، اگر بخش شروع یا گام را حذف کنم چه اتفاقی می‌افتد؟

پاسخ: در جاوا هر سه بخش for اختیاری هستند، اما سمی‌کالن‌های جداکننده حتماً باید سر جایشان باشند. مثلاً for (;;) یک حلقه بی‌نهایت معتبر است که معادل while (true) است. اگر بخش شروع را حذف کنید، متغیر شمارنده باید قبل از حلقه تعریف شده باشد. اگر بخش گام را حذف کنید، باید داخل بدنه حلقه شمارنده را به‌روزرسانی کنید، وگرنه حلقه بی‌نهایت می‌شود. اما در عمل، در سطح مقدماتی همیشه از شکل کامل استفاده کنید تا کد خوانا بماند و کمتر پیش بیاید که چیزی را فراموش کنید.

جمع‌بندی و نکات کلیدی

مرور سریع مطالب این هفته

شرط‌ها

  • if برای یک تصمیم ساده؛ اگر شرط درست بود، بدنه اجرا می‌شود.
  • if-else برای دو مسیر؛ دقیقاً یکی از دو بدنه اجرا می‌شود.
  • else-if برای چند مسیر؛ به محض رسیدن به اولین شرط درست، از نردبان خارج می‌شود.
  • همیشه شرط محدودتر را بالاتر بنویسید.
  • شرط تودرتو برای فیلترهای چندمرحله‌ای با پیام خطای متفاوت.
  • هرگز بعد از پرانتز if سمی‌کالن نگذارید.
  • در شرط از == استفاده کنید، نه =.

switch

  • برای مقایسه یک متغیر با چند مقدار ثابت.
  • در نسخه سنتی، بعد از هر case break بنویسید تا نفوذ رخ ندهد.
  • در نسخه مدرن (جاوا ۱۴+)، از سینتکس -> استفاده کنید.
  • در نسخه مدرن، switch می‌تواند مقدار برگرداند و مستقیماً به متغیر نسبت داده شود.
  • در نسخه مدرن، می‌توان چند مقدار را با کاما در یک case گروه کرد.

حلقه‌ها

  • while: بررسی شرط قبل از اجرا؛ ممکن است صفر بار اجرا شود.
  • do-while: بررسی شرط بعد از اجرا؛ حداقل یک بار اجرا می‌شود. سمی‌کالن انتهایی الزامی است.
  • for: شروع، شرط و گام در یک خط؛ مناسب وقتی تعداد تکرار مشخص است.
  • حلقه تودرتو: حلقه درونی برای هر دور حلقه بیرونی، کامل اجرا می‌شود.
  • در حلقه‌های بی‌نهایت، فراموش نکنید شرط خروج با break داشته باشید.

break و continue

  • break حلقه را کاملاً متوقف می‌کند.
  • continue فقط دور فعلی را رد می‌کند.
  • در حلقه while، مراقب باشید continue قبل از به‌روزرسانی شمارنده نباشد.
  • در حلقه‌های تودرتو، break فقط از حلقه درونی خارج می‌شود.
