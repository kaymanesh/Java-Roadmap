جزوه آموزشی زبان برنامه‌نویسی جاوا — دوره مقدماتی

تا اینجا برنامه‌های ما فقط با چند متغیر ساده کار می‌کردند. اما برنامه‌های واقعی با حجم زیادی از داده سروکار دارند. در این هفته یاد می‌گیریم چطور ده‌ها یا صدها مقدار را در یک ساختار منظم نگه داریم، چطور کدهای طولانی را به بخش‌های کوچک و قابل استفاده مجدد بشکنیم، چطور با متن‌ها حرفه‌ای‌تر کار کنیم و در نهایت یاد بگیریم وقتی برنامه رفتار اشتباهی دارد، چطور علت را پیدا کنیم.

آرایه‌های یک‌بعدی

نگهداری چند مقدار هم‌نوع در یک ساختار منظم

چرا به آرایه نیاز داریم؟

فرض کنید می‌خواهید نمرات ۳۰ دانشجو را در برنامه ذخیره کنید. اگر بخواهید با متغیرهای ساده کار کنید، باید ۳۰ متغیر با ۳۰ نام مختلف بسازید: score1، score2، تا score30. این کار نه‌تنها خسته‌کننده است، بلکه مدیریتش تقریباً غیرممکن می‌شود. برای محاسبه میانگین باید ۳۰ متغیر را با هم جمع کنید، برای پیدا کردن بالاترین نمره باید ۳۰ بار مقایسه انجام دهید و برای مرتب‌سازی کار پیچیده‌تر هم می‌شود.

آرایه یک ساختار است که چند مقدار از یک نوع را در یک ردیف کنار هم نگه می‌دارد و با یک نام واحد به همه دسترسی می‌دهد. با آرایه، همان ۳۰ نمره در یک متغیر با نام scores ذخیره می‌شوند و با یک حلقه می‌توان همه‌شان را پردازش کرد.

تعریف ساده آرایه مثل یک ردیف جعبه شماره‌دار است. همه جعبه‌ها هم‌جنس‌اند و هر کدام یک شماره (اندیس) دارند. با شماره هر جعبه می‌توانیم مقدار داخلش را بخوانیم یا عوض کنیم. تعداد جعبه‌ها هنگام ساخت مشخص می‌شود و بعد از آن قابل تغییر نیست.

سه مرحله ساخت آرایه

هر وقت با آرایه کار می‌کنید، سه مرحله را از هم جدا نگه دارید. این تفکیک، هم درک برنامه را بالا می‌برد و هم در رفع خطا کمک می‌کند.

  1. ۱
    اعلان (Declaration): یک متغیر تعریف می‌کنیم که می‌تواند به یک آرایه اشاره کند. در این مرحله هنوز هیچ فضایی در حافظه ساخته نشده است.
  2. ۲
    تخصیص حافظه (Allocation): با کلمه کلیدی new فضای لازم در حافظه ساخته می‌شود. تعداد خانه‌ها در همین مرحله مشخص می‌شود.
  3. ۳
    مقداردهی (Initialization): مقادیر اولیه در خانه‌ها قرار می‌گیرند. این کار می‌تواند هنگام ساخت انجام شود یا بعداً خانه‌به‌خانه پر شود.
Java — سه مرحله جداگانه 
public class Lesson {
    public static void main(String[] args) {
        int[] scores;              // declaration
        scores = new int[3];       // allocation: سه خانه
        scores[0] = 18;            // initialization
        scores[1] = 15;
        scores[2] = 20;
        System.out.println(scores[1]);
    }
}
خروجی 
15

برای آرایه‌های کوچک می‌توان هر سه مرحله را در یک خط جمع کرد. جاوا از این شکل استقبال می‌کند و خوانایی برنامه هم بالاتر می‌رود.

Java — مقداردهی یکجا 
public class Lesson {
    public static void main(String[] args) {
        int[] scores = {18, 15, 20};
        System.out.println(scores.length);
    }
}

اندیس و طول آرایه

شماره هر خانه را اندیس می‌گوییم. در جاوا اولین خانه اندیس 0 دارد، نه ۱. برای آرایه‌ای با n خانه، اندیس‌های معتبر از 0 تا n - 1 هستند. تعداد خانه‌ها را با ویژگی length می‌خوانیم که بعد از نام آرایه و بدون پرانتز می‌آید.

پیمایش آرایه

برای دیدن یا پردازش همه خانه‌ها، از حلقه استفاده می‌کنیم. دو شکل رایج وجود دارد که هر کدام کاربرد خودش را دارد.

شکل اول: حلقه for با اندیس

در این شکل، متغیر شمارنده نقش اندیس را دارد. هر وقت به شماره خانه نیاز داشته باشید (مثلاً برای تغییر مقدار یا مقایسه با خانه دیگر)، باید از این شکل استفاده کنید.

Java 
public class Lesson {
    public static void main(String[] args) {
        int[] values = {4, 7, 2};
        for (int i = 0; i < values.length; i++) {
            System.out.println(values[i]);
        }
    }
}

شکل دوم: حلقه enhanced for

اگر فقط می‌خواهید مقادیر را بخوانید و به شماره خانه کاری ندارید، می‌توانید از enhanced for استفاده کنید. این شکل خواناتر است و امکان اشتباه در اندیس را از بین می‌برد.

Java 
public class Lesson {
    public static void main(String[] args) {
        int[] values = {4, 7, 2};
        for (int value : values) {
            System.out.println(value);
        }
    }
}
کدام شکل را انتخاب کنیم؟ اگر در بدنه حلقه به اندیس نیاز دارید یا می‌خواهید خانه‌ها را تغییر دهید، از for با اندیس استفاده کنید. اگر فقط می‌خواهید مقادیر را بخوانید و پردازش کنید، enhanced for خواناتر و امن‌تر است.

تغییر عناصر آرایه

برای تغییر مقدار یک خانه، از اندیس استفاده می‌کنیم. مثال زیر همه خانه‌ها را دو برابر می‌کند:

Java 
public class Lesson {
    public static void main(String[] args) {
        int[] values = {3, 5, 8};
        for (int i = 0; i < values.length; i++) {
            values[i] = values[i] * 2;
        }
        for (int value : values) {
            System.out.println(value);
        }
    }
}
enhanced for برای تغییر مناسب نیست اگر در enhanced for متغیر value را تغییر دهید، مقدار داخل آرایه عوض نمی‌شود. متغیر value فقط یک کپی از مقدار خانه است. برای تغییر واقعی خانه‌ها، حتماً از values[i] = ... استفاده کنید.

عملیات رایج روی آرایه

برخی عملیات‌ها را تقریباً همیشه با آرایه انجام می‌دهید: محاسبه مجموع، پیدا کردن بزرگ‌ترین یا کوچک‌ترین مقدار، شمارش عناصر خاص و جستجو. این‌ها پایه بسیاری از تمرین‌های برنامه‌نویسی هستند.

Java — مجموع و میانگین 
public class Lesson {
    public static void main(String[] args) {
        int[] scores = {18, 15, 20, 12, 17};
        int sum = 0;
        for (int score : scores) {
            sum += score;
        }
        double average = (double) sum / scores.length;
        System.out.println("Sum: " + sum);
        System.out.println("Average: " + average);
    }
}
Java — بزرگ‌ترین مقدار 
public class Lesson {
    public static void main(String[] args) {
        int[] scores = {18, 15, 20, 12, 17};
        int max = scores[0];
        for (int i = 1; i < scores.length; i++) {
            if (scores[i] > max) {
                max = scores[i];
            }
        }
        System.out.println("Max: " + max);
    }
}
مقدار اولیه درست انتخاب کنید برای پیدا کردن بزرگ‌ترین مقدار، متغیر max را با scores[0] شروع کنید، نه با صفر. اگر همه مقادیر آرایه منفی باشند، شروع از صفر نتیجه غلط می‌دهد چون صفر از همه آن‌ها بزرگ‌تر است.

کپی کردن آرایه

یک نکته ظریف: اگر بنویسید int[] copy = original;، در واقع دو نام برای یک آرایه ساخته‌اید، نه دو آرایه جداگانه. برای کپی واقعی، باید خانه‌ها را یکی‌یکی کپی کنید یا از متدهای آماده استفاده کنید.

Java — کپی واقعی آرایه 
import java.util.Arrays;

public class Lesson {
    public static void main(String[] args) {
        int[] original = {1, 2, 3};

        // روش اول: حلقه
        int[] copy1 = new int[original.length];
        for (int i = 0; i < original.length; i++) {
            copy1[i] = original[i];
        }

        // روش دوم: متد آماده
        int[] copy2 = Arrays.copyOf(original, original.length);

        copy1[0] = 99;
        System.out.println(original[0]);   // 1
        System.out.println(copy1[0]);      // 99
    }
}

متدهای آماده کلاس Arrays

جاوا یک کلاس کمکی به نام Arrays دارد که کارهای رایج را بسیار ساده می‌کند. باید در ابتدای فایل آن را import کنید: import java.util.Arrays;

متد کار
Arrays.toString(arr)تبدیل آرایه به رشته خوانا برای چاپ
Arrays.sort(arr)مرتب‌سازی صعودی (برای اعداد)
Arrays.fill(arr, val)پر کردن همه خانه‌ها با یک مقدار
Arrays.copyOf(arr, len)ساخت کپی از آرایه با طول مشخص
Arrays.equals(a, b)مقایسه محتوای دو آرایه
Java — نمونه استفاده از Arrays 
import java.util.Arrays;

public class Lesson {
    public static void main(String[] args) {
        int[] numbers = {5, 2, 8, 1, 9};
        Arrays.sort(numbers);
        System.out.println(Arrays.toString(numbers));

        int[] filled = new int[3];
        Arrays.fill(filled, 7);
        System.out.println(Arrays.toString(filled));
    }
}

آرایه‌های دوبعدی

نمایش جدول‌های سطری-ستونی در حافظه

آرایه دوبعدی چیست؟

گاهی داده‌ها دو بُعد دارند؛ مثلاً نمرات سه آزمون از چهار دانشجو یک جدول ۴ در ۳ می‌سازد. برای چنین حالتی از آرایه دوبعدی استفاده می‌کنیم. در واقع آرایه دوبعدی در جاوا «آرایه‌ای از آرایه‌ها» است؛ یعنی هر سطر، خودش یک آرایه است.

تعریف ساده آرایه دوبعدی مثل یک جدول است که هم سطر دارد هم ستون. برای دسترسی به هر خانه، باید دو اندیس بدهید: اول شماره سطر، بعد شماره ستون.
Java — ساخت آرایه دوبعدی 
public class Lesson {
    public static void main(String[] args) {
        // روش اول: با new و ابعاد مشخص
        int[][] grid = new int[2][3];   // 2 سطر × 3 ستون

        // روش دوم: مقداردهی یکجا
        int[][] matrix = {
            {1, 2, 3},
            {4, 5, 6}
        };

        System.out.println(matrix[1][2]);   // 6
    }
}

پیمایش با دو حلقه تودرتو

برای پیمایش همه خانه‌های یک آرایه دوبعدی، به دو حلقه نیاز داریم: یک حلقه بیرونی برای سطرها و یک حلقه درونی برای ستون‌ها.

Java — چاپ جدول 
public class Lesson {
    public static void main(String[] args) {
        int[][] table = {
            {1, 2, 3},
            {4, 5, 6}
        };
        for (int row = 0; row < table.length; row++) {
            for (int col = 0; col < table[row].length; col++) {
                System.out.print(table[row][col] + " ");
            }
            System.out.println();
        }
    }
}
خروجی 
1 2 3 
4 5 6
length در آرایه دوبعدی table.length تعداد سطرها را می‌دهد. table[row].length تعداد ستون‌های همان سطر را. برای اطمینان از درستی حلقه، در شرط داخلی از table[row].length استفاده کنید، نه table.length.

آرایه‌های دندانه‌دار (Jagged)

چون هر سطر خودش یک آرایه مستقل است، می‌توان سطرهایی با طول متفاوت داشت. به چنین ساختاری آرایه دندانه‌دار یا jagged array می‌گوییم.

Java — سطرهای با طول متفاوت 
public class Lesson {
    public static void main(String[] args) {
        int[][] jagged = new int[3][];
        jagged[0] = new int[] {7, 8};
        jagged[1] = new int[] {9};
        jagged[2] = new int[] {1, 2, 3};

        for (int row = 0; row < jagged.length; row++) {
            for (int col = 0; col < jagged[row].length; col++) {
                System.out.print(jagged[row][col] + " ");
            }
            System.out.println();
        }
    }
}
خروجی 
7 8 
9 
1 2 3
سطرهای null وقتی می‌نویسید new int[3][]، سه جایگاه برای سطر ساخته می‌شود، اما خود سطرها هنوز ساخته نشده‌اند و مقدارشان null است. اگر قبل از ساختن سطر، بخواهید طول یا خانه‌های آن را بخوانید، برنامه با NullPointerException متوقف می‌شود. اول باید هر سطر را با new int[...] بسازید، بعد از آن استفاده کنید.

مثال کاربردی: مجموع هر سطر

یکی از رایج‌ترین کارها روی آرایه دوبعدی، محاسبه مجموع هر سطر یا هر ستون است. مثال زیر مجموع هر سطر را جداگانه حساب می‌کند.

Java — مجموع هر سطر 
public class Lesson {
    public static void main(String[] args) {
        int[][] sales = {
            {10, 20, 30},
            {5, 15, 25}
        };

        for (int row = 0; row < sales.length; row++) {
            int rowSum = 0;
            for (int col = 0; col < sales[row].length; col++) {
                rowSum += sales[row][col];
            }
            System.out.println("Row " + row + " sum: " + rowSum);
        }
    }
}

متدها

شکستن کد به بخش‌های کوچک، نام‌دار و قابل استفاده مجدد

چرا به متد نیاز داریم؟

تا اینجا همه کد را داخل main می‌نوشتیم. اما وقتی برنامه بزرگ‌تر می‌شود، main به یک بلوک طولانی و غیرقابل فهم تبدیل می‌شود. سه مشکل اصلی پیش می‌آید. اول، پیدا کردن بخش‌های خاص کد سخت می‌شود. دوم، اگر جایی نیاز به تکرار یک منطق باشد، مجبورید همان کد را چند بار بنویسید. سوم، اگر بعداً بخواهید همان منطق را تغییر دهید، باید همه‌جا را دست بزنید و احتمال فراموش کردن یکی از نسخه‌ها زیاد است.

متد یک بسته کد نام‌دار است که یک کار مشخص انجام می‌دهد. با متد، همان منطق یک بار نوشته می‌شود و هر جا لازم شد فقط با نامش صدایش می‌زنیم. نتیجه این است که main کوتاه و خوانا می‌ماند، تکرار کد کم می‌شود و تغییر منطق در یک نقطه کافی است.

تعریف ساده متد مثل یک دستور آشپزی است: یک اسم دارد، ممکن است چند مواد اولیه (پارامتر) بگیرد، و یک نتیجه بدهد. هر وقت خواستیم، فقط اسم دستور را صدا می‌زنیم.

ساختار یک متد

شکل کلی تعریف متد در جاوا به این صورت است:

Java — ساختار کلی 
returnType methodName(parameterList) {
    // body
    return value;
}

هر بخش این ساختار یک نقش مشخص دارد:

  • نوع بازگشتی (Return Type): نوع داده‌ای که متد در پایان برمی‌گرداند؛ مثلاً int، double، boolean یا String. اگر متد چیزی برنگرداند، می‌نویسیم void.
  • نام متد: یک اسم معنادار که کارش را برساند. طبق سبک Camel Case نوشته می‌شود.
  • لیست پارامترها: ورودی‌هایی که متد برای انجام کارش لازم دارد. می‌تواند خالی باشد، یک پارامتر داشته باشد یا چند پارامتر.
  • بدنه: دستوراتی که هنگام اجرای متد انجام می‌شوند.
  • return: مقدار نتیجه را برمی‌گرداند. اگر نوع بازگشتی void است، این خط اختیاری است یا می‌تواند برای خروج زودتر استفاده شود.

پارامتر و آرگومان

دو اصطلاح نزدیک به هم وجود دارد که برخی افراد آن‌ها را با هم اشتباه می‌گیرند. تفاوت در جای استفاده است، نه در ماهیت.

  • پارامتر: متغیری که در تعریف متد نوشته می‌شود. مثلاً int a, int b در تعریف add.
  • آرگومان: مقدار واقعی که هنگام فراخوانی متد داده می‌شود. مثلاً ۵ و ۷ در add(5, 7).

هنگام فراخوانی، آرگومان‌ها داخل پارامترها کپی می‌شوند و متد با آن کپی‌ها کار می‌کند. یعنی اگر داخل متد پارامتر را تغییر دهید، متغیر اصلی که در فراخوانی استفاده کردید تغییر نمی‌کند. تنها استثنا آرایه‌ها هستند که در بخش بعدی توضیح داده می‌شوند.

دو نوع متد داریم. متدی که نتیجه‌ای برای استفاده بیرون برمی‌گرداند، و متدی که فقط کاری انجام می‌دهد. تفاوت در نوع بازگشتی است.

کلمه static به چه معناست؟

Overloading و Type Casting

چند متد با یک نام و تبدیل نوع داده

Method Overloading چیست؟

جاوا اجازه می‌دهد چند متد با نام یکسان اما لیست پارامترهای متفاوت داشته باشیم. به این کار Overloading می‌گوییم. کامپایلر هنگام فراخوانی، بر اساس تعداد و نوع آرگومان‌ها تصمیم می‌گیرد کدام نسخه را اجرا کند.

کاربرد این ویژگی زمانی است که یک عملیات منطقی واحد دارید اما می‌خواهید با انواع یا تعداد مختلفی از داده کار کند. مثلاً یک متد add که هم دو عدد صحیح جمع کند، هم سه عدد صحیح، هم دو عدد اعشاری. بدون overloading باید برای هر نسخه یک نام جداگانه می‌گذاشتید: addInts، addThreeInts، addDoubles. با overloading، همه با نام add صدا زده می‌شوند.

چه چیزی overloading نیست؟

دو مورد وجود دارد که ممکن است شبیه overloading به نظر برسند، اما کامپایلر آن‌ها را رد می‌کند.

  • فقط تفاوت در نام پارامتر: اگر دو متد با نام یکسان و پارامترهای یکسان داشته باشید، فقط نام پارامترها متفاوت باشد، کامپایلر می‌گوید این دو متد یکسان‌اند و خطا می‌دهد.
  • فقط تفاوت در نوع بازگشتی: اگر دو متد دقیقاً یک امضا داشته باشند و فقط return type متفاوت باشد، باز هم خطا می‌دهد. نوع بازگشتی بخشی از امضای متد نیست.
Java — مثال خطا (اجرا نکنید) 
// خطا: فقط نام پارامترها متفاوت است
int add(int a, int b) { return a + b; }
int add(int x, int y) { return x + y; }

// خطا: فقط نوع بازگشتی متفاوت است
int add(int a, int b) { return a + b; }
double add(int a, int b) { return a + b; }
امضای متد امضای متد (Method Signature) شامل نام متد و لیست پارامترها است. نوع بازگشتی جزو امضا نیست. به همین دلیل برای overloading باید یا تعداد پارامترها یا نوع پارامترها متفاوت باشد.

Type Casting چیست؟

Type Casting یعنی تبدیل یک مقدار از یک نوع داده به نوع دیگر. در جاوا دو حالت دارد: تبدیل گسترده‌کننده که خودکار انجام می‌شود، و تبدیل محدودکننده که باید صریحاً نوشته شود.

تبدیل گسترده‌کننده (Widening)

وقتی از یک نوع کوچک‌تر (مثل int) به یک نوع بزرگ‌تر (مثل double) تبدیل می‌کنید، هیچ اطلاعاتی از دست نمی‌رود. جاوا این تبدیل را خودکار انجام می‌دهد.

Java — widening 
int whole = 7;
double widened = whole;   // 7.0 — خودکار

تبدیل محدودکننده (Narrowing)

وقتی از یک نوع بزرگ‌تر به یک نوع کوچک‌تر تبدیل می‌کنید، ممکن است بخشی از داده از دست برود. مثلاً تبدیل double به int بخش اعشاری را حذف می‌کند. این تبدیل باید صریحاً نوشته شود.

Java — narrowing 
double price = 2.9;
int narrowed = (int) price;   // 2 — بخش اعشاری حذف می‌شود
نکته مهم تبدیل double به int بخش اعشاری را حذف می‌کند، نه گرد. یعنی 2.9 می‌شود 2، نه 3. اگر می‌خواهید گرد کنید، باید از Math.round استفاده کنید که در هفته‌های بعد توضیح داده می‌شود.

تقسیم صحیح و تله رایج

یکی از رایج‌ترین اشتباهات مبتدیان، انتظار نتیجه اعشاری از تقسیم دو عدد صحیح است. وقتی هر دو طرف تقسیم از نوع int باشند، جاوا تقسیم صحیح انجام می‌دهد و بخش اعشاری را کاملاً حذف می‌کند.

Java 
int a = 7;
int b = 2;

System.out.println(a / b);              // 3
System.out.println((double) a / b);     // 3.5
System.out.println((double) (a / b));   // 3.0
ترتیب cast اهمیت دارد (double) a / b ابتدا a را به double تبدیل می‌کند و بعد تقسیم انجام می‌شود. نتیجه اعشاری است. اما (double) (a / b) ابتدا تقسیم صحیح را انجام می‌دهد (نتیجه 3)، بعد آن را به double تبدیل می‌کند (نتیجه 3.0). تفاوت خیلی مهم است.

split و regex متد split در واقع یک الگوی regex می‌گیرد، نه یک رشته ساده. برای کاما و اکثر کاراکترهای معمولی مشکلی پیش نمی‌آید، اما برای نقطه باید دقت کنید. نقطه در regex معنای ویژه دارد، پس برای جدا کردن با نقطه واقعی باید بنویسید split("\\.").

مقایسه رشته‌ها: equals در برابر ==

این یکی از رایج‌ترین دام‌های مبتدیان است. برای مقایسه محتوای رشته‌ها هرگز از == استفاده نکنید.

Java 
String a = new String("Java");
String b = new String("Java");

System.out.println(a == b);      // false
System.out.println(a.equals(b)); // true
عملگر / متد چه چیزی را مقایسه می‌کند نتیجه برای دو رشته هم‌محتوا
== آدرس حافظه (آیا هر دو به یک شیء اشاره می‌کنند) معمولاً false
equals() محتوای دو رشته true
قانون طلایی برای مقایسه محتوای رشته‌ها همیشه از equals() استفاده کنید. تنها استثنا زمانی است که واقعاً می‌خواهید بدانید آیا هر دو متغیر به یک شیء یکسان اشاره می‌کنند.

مثال کاربردی: استخراج نام کاربری از ایمیل

با ترکیب indexOf و substring می‌توان کارهای مفیدی انجام داد. مثال زیر بخش قبل از @ را از ایمیل جدا می‌کند.

Java 
String email = "sara@example.com";
int at = email.indexOf("@");
if (at >= 0) {
    String username = email.substring(0, at);
    System.out.println(username);   // sara
} else {
    System.out.println("Invalid email");
}
همیشه حالت پیدا نشدن را بررسی کنید اگر indexOf مقدار -1 بدهد و شما بدون بررسی از آن در substring استفاده کنید، برنامه با خطا متوقف می‌شود. شرط if (at >= 0) این مشکل را حل می‌کند.

تغییرناپذیری String

رشته‌ها در جاوا تغییرناپذیر یا immutable هستند. یعنی بعد از ساخت، محتوایشان قابل تغییر نیست. اگر به نظر برسد که داریم محتوای رشته را تغییر می‌دهیم، در واقع یک رشته جدید ساخته می‌شود و متغیر به آن اشاره می‌کند.

تصویر ذهنی فرض کنید روی یک کاغذ نوشته‌اید «Java». نمی‌توانید «J» را پاک کنید و «K» بنویسید. برای اینکه «Kava» داشته باشید، باید یک کاغذ جدید بردارید. رشته‌ها در جاوا همین‌طورند.
Java — تغییرناپذیری در عمل 
String first = "Java";
first.concat("!");              // نتیجه نادیده گرفته می‌شود
System.out.println(first);     // Java

String second = first.concat("!");
System.out.println(first);     // Java
System.out.println(second);    // Java!

String Pool

String Pool یک ناحیه ویژه در حافظه است که جاوا رشته‌های literal را در آن نگه می‌دارد. وقتی می‌نویسید String s = "Java";، جاوا ابتدا بررسی می‌کند آیا رشته‌ای با همین محتوا در Pool وجود دارد یا نه. اگر باشد، همان شیء موجود استفاده می‌شود. اگر نباشد، یک شیء جدید ساخته و در Pool ذخیره می‌شود.

اما اگر از new String("Java") استفاده کنید، جاوا یک شیء جدید در Heap بیرون از Pool می‌سازد. به همین دلیل دو متغیری که با literal مقداردهی شده‌اند به یک شیء اشاره می‌کنند، ولی یکی که با new ساخته شده به شیء جداگانه.

Java 
String s1 = "Java";              // literal، در Pool
String s2 = "Java";              // همان شیء از Pool
String s3 = new String("Java");  // شیء جدید، بیرون از Pool

System.out.println(s1 == s2);      // true
System.out.println(s1 == s3);      // false
System.out.println(s1.equals(s3)); // true
نکته عملی برای همین است که مقایسه با == قابل اعتماد نیست. حتی اگر امروز جواب درست بدهد، در آینده با تغییر جزئی در کد ممکن است جواب متفاوت بدهد. همیشه از equals استفاده کنید.

StringBuilder: ابزار تغییرپذیر

چون String تغییرناپذیر است، هر بار که محتوای آن را عوض می‌کنید، در واقع یک شیء جدید ساخته می‌شود. اگر در یک حلقه هزار بار این کار را انجام دهید، هزار شیء ساخته و دور ریخته می‌شود. برای این حالت‌ها، از StringBuilder استفاده می‌کنیم که تغییرپذیر است. متدهای append، insert، delete و reverse محتوای همان شیء را تغییر می‌دهند، نه ساختن شیء جدید.

Java — ساخت و append 
StringBuilder builder = new StringBuilder("Java");
builder.append(" 25");
System.out.println(builder);   // Java 25
Java — insert و delete 
StringBuilder builder = new StringBuilder("Java 25");
builder.insert(4, "-");
System.out.println(builder);   // Java- 25

builder.delete(4, 5);
System.out.println(builder);   // Java 25
Java — reverse و toString 
StringBuilder builder = new StringBuilder("Java 25");
builder.reverse();
String result = builder.toString();
System.out.println(result);   // 52 avaJ

String یا StringBuilder؟ کدام را انتخاب کنیم؟

String را انتخاب کنید

وقتی متن ثابت است یا تغییرات اندک دارد. وقتی می‌خواهید در فیلد یا پارامتر از آن استفاده کنید. وقتی خوانایی مهم‌تر از بهینه‌سازی است.

وقتی در حلقه یا به تعداد زیاد متن را تغییر می‌دهید. وقتی می‌خواهید از ساخت و دور ریختن مکرر شیء جلوگیری کنید. برای پردازش متن‌های بزرگ.

تبدیل بین دو از String به StringBuilder با new StringBuilder(s) و از StringBuilder به String با sb.toString(). برای مقایسه محتوای دو StringBuilder، همیشه اول به String تبدیل کنید و بعد equals بزنید.

Debugger و عیب‌یابی

وقتی برنامه کار نکرد، چطور علت را پیدا کنیم

سه دسته خطا

خطاهای برنامه‌نویسی به سه دسته اصلی تقسیم می‌شوند. شناختن این دسته‌ها، اولین قدم برای عیب‌یابی درست است.

دسته کِی رخ می‌دهد مثال
خطای کامپایل قبل از اجرا، هنگام ترجمه کد جا افتادن سمی‌کالن، اشتباه تایپی، نوع داده ناسازگار
خطای زمان اجرا در حین اجرای برنامه تقسیم بر صفر، اندیس آرایه نامعتبر، null بودن متغیر
خطای منطقی در حین اجرا، اما برنامه متوقف نمی‌شود خروجی اشتباه، شرط با ترتیب غلط، محاسبه نادرست

خطاهای کامپایل

خطاهای کامپایل قبل از اجرای برنامه رخ می‌دهند. کد حتی یک خط هم اجرا نمی‌شود. این خطاها معمولاً واضح‌اند و کامپایلر می‌گوید مشکل در کدام خط است.

Java — چند نمونه خطای کامپایل 
System.out.println("Hi"     // خطا: پرانتز بسته نشده

int n = "3";                // خطا: نوع ناسازگار

pritn(n);                   // خطا: نام متد اشتباه

int x;
System.out.println(x);      // خطا: متغیر مقداردهی نشده

خطاهای زمان اجرا

این خطاها هنگام اجرای برنامه رخ می‌دهند. یعنی کد کامپایل شده، اما در مسیر اجرا به مشکل خورده و برنامه متوقف شده است. هر خطای زمان اجرا یک نام دارد که معمولاً به Exception ختم می‌شود.

نام خطا علت مثال
ArrayIndexOutOfBoundsExceptionدسترسی به اندیس نامعتبر آرایهarr[10] برای آرایه سه‌عضوی
NullPointerExceptionاستفاده از شیئی که null استString s = null; s.length();
ArithmeticExceptionتقسیم بر صفر10 / 0
NumberFormatExceptionتبدیل رشته غیرعددی به عددInteger.parseInt("abc")
StringIndexOutOfBoundsExceptionاندیس نامعتبر در رشته"Java".charAt(10)

خواندن پیام خطا

وقتی خطایی رخ می‌دهد، جاوا یک پیام با جزئیات می‌دهد که به آن Stack Trace می‌گویند. این پیام دو بخش مهم دارد: نوع خطا و محل خطا.

Stack Trace نمونه 
Exception in thread "main" java.lang.ArrayIndexOutOfBoundsException: Index 5 out of bounds for length 3
    at Lesson.main(Lesson.java:5)

در این پیام:

  • نوع خطا: ArrayIndexOutOfBoundsException. یعنی به اندیس نامعتبر دسترسی پیدا کرده‌اید.
  • جزئیات: Index 5 out of bounds for length 3. یعنی اندیس ۵ در آرایه‌ای با طول ۳ استفاده شده.
  • محل: Lesson.java:5. یعنی خط ۵ فایل Lesson.java.
Stack Trace را از پایین به بالا بخوانید آخرین خط معمولاً می‌گوید دقیقاً چه نوع خطایی رخ داده و در کدام خط از کد شما. بالاتر از آن، مسیر فراخوانی متدها نشان داده می‌شود. برای مبتدی، مهم‌ترین خط، همان خط اولی است که به کد خودتان اشاره می‌کند.

خطاهای منطقی

این سخت‌ترین دسته است. برنامه کامپایل می‌شود، اجرا هم می‌شود، هیچ خطایی نمی‌دهد، اما خروجی اشتباه است. برای پیدا کردن این خطاها، به Debugger نیاز دارید.

Java — نمونه خطای منطقی 
int score = 95;

if (score >= 60) {
    System.out.println("Pass");
} else if (score >= 90) {
    System.out.println("Excellent");
}

برای نمره ۹۵، خروجی Pass است، نه Excellent. چون شرط اول score >= 60 برای ۹۵ هم درست است و برنامه به شاخه دوم نمی‌رسد. رفع مشکل، جابه‌جا کردن ترتیب است: شرط سخت‌گیرانه‌تر بالا، کلی‌تر پایین.

Breakpoint چیست؟

Breakpoint یک نشانه است که روی یک خط از کد می‌گذارید. وقتی برنامه در حالت Debug اجرا می‌شود و به آن خط می‌رسد، اجرا متوقف می‌شود و شما می‌توانید وضعیت همه متغیرها را ببینید. در IntelliJ IDEA، برای گذاشتن Breakpoint کافی است روی نوار کناری کنار شماره خط کلیک کنید تا یک دایره قرمز ظاهر شود.

چرا مفید است؟ گاهی خطا پیام نمی‌دهد، فقط خروجی اشتباه است. Breakpoint اجازه می‌دهد قدم‌به‌قدم ببینید مقادیر متغیرها در هر لحظه چه هستند و کجا مقدار غیرمنتظره ظاهر می‌شود.

ابزارهای قدم‌به‌قدم

وقتی برنامه در یک Breakpoint متوقف شد، چند دکمه دارید که با آن‌ها اجرا را قدم‌به‌قدم جلو می‌برید.

دکمه کلید میانبر کاری که می‌کند
Step Over F8 خط فعلی را کامل اجرا می‌کند و به خط بعدی می‌رود. اگر خط فعلی فراخوانی متد باشد، وارد متد نمی‌شود.
Step Into F7 اگر خط فعلی فراخوانی متد باشد، وارد بدنه آن متد می‌شود تا داخلش را ببینید.
Step Out Shift+F8 از متد فعلی بیرون می‌آید و به فراخواننده بازمی‌گردد.
Resume F9 ادامه می‌دهد تا Breakpoint بعدی یا پایان برنامه.

یک مثال عملی

Java — DebuggerDemo.java 
public class DebuggerDemo {
    public static void main(String[] args) {
        String text = "Java";
        int position = text.indexOf("v");
        String result = getLetter(text, position);
        System.out.println(result);
    }

    static String getLetter(String text, int index) {
        return String.valueOf(text.charAt(index));
    }
}

برای عیب‌یابی این برنامه با Debugger، این مراحل را دنبال کنید:

  1. ۱
    فایل را در IntelliJ IDEA باز کنید.
  2. ۲
    در نوار کناری، کنار خط String result = ... کلیک کنید تا Breakpoint قرمز ظاهر شود.
  3. ۳
    از منوی Run گزینه Debug را انتخاب کنید (یا Shift+F9).
  4. ۴
    برنامه در Breakpoint متوقف می‌شود. در پنل Variables می‌بینید که text = "Java" و position = 2.
  5. ۵
    با F8 (Step Over) از روی خط فراخوانی عبور کنید. نتیجه v در متغیر result ذخیره می‌شود.
  6. ۶
    اگر می‌خواهید داخل getLetter را ببینید، برنامه را دوباره اجرا کنید و به‌جای F8 از F7 (Step Into) استفاده کنید.
  7. ۷
    با F9 (Resume) تا پایان برنامه ادامه دهید.
تمرین تشخیصی فرض کنید indexOf("x") را جایگزین کرده‌اید. حالا position برابر -1 می‌شود. اگر Breakpoint را روی خط String result = ... بگذارید، قبل از اجرای آن متوقف می‌شوید و می‌بینید position = -1. اینجا یک فرصت عالی برای پیش‌بینی خطا دارید: charAt(-1) باعث StringIndexOutOfBoundsException می‌شود. بدون Debugger هم می‌توانستید این را پیش‌بینی کنید، اما Debugger با نشان دادن مقدار واقعی، اطمینان می‌دهد.

روال کوتاه عیب‌یابی

  1. ۱

  2. ۲

  3. ۳

  4. ۴

  5. ۵

تمرین‌ها و پروژه

پروژه کلاسی

سامانه مدیریت نمرات دانشجویان

برنامه‌ای بنویسید که نمرات چند دانشجو را از کاربر دریافت کند و در آرایه ذخیره کند. سپس با متدهای جداگانه، سه کار زیر را انجام دهد: محاسبه میانگین کلاس، پیدا کردن بالاترین و پایین‌ترین نمره به همراه نام دانشجو، و مرتب‌سازی نمرات از بزرگ به کوچک. نام هر دانشجو باید همراه با نمره‌اش حفظ شود و ترتیب نام‌ها و نمرات در همه محاسبات هماهنگ بماند.

ساختار پیشنهادی
  1. دو آرایه هم‌اندازه: یکی برای نام دانشجوها، یکی برای نمره‌ها.
  2. سه متد جداگانه: یکی برای میانگین، یکی برای پیدا کردن بالاترین و پایین‌ترین، یکی برای مرتب‌سازی.
  3. در پایان، خروجی‌ها با پیام‌های واضح چاپ شوند.
راهنمای گام‌به‌گام
  1. ۱
    ابتدا تعداد دانشجوها را با Scanner از کاربر بگیرید.
  2. ۲
    دو آرایه بسازید: String[] names = new String[count]; و double[] scores = new double[count];.
  3. ۳
    با یک حلقه for از ۰ تا count - 1، در هر دور نام و نمره یک دانشجو را بگیرید و در خانه‌های متناظر ذخیره کنید. دقت کنید اندیس‌های دو آرایه هماهنگ باشند.
  4. ۴
    متدی به نام calculateAverage(double[] scores) بنویسید که مجموع نمرات را حساب کند و با (double) sum / scores.length میانگین را برگرداند.
  5. ۵
    متدی به نام findMaxMin(String[] names, double[] scores) بنویسید که با یک حلقه، اندیس بزرگ‌ترین و کوچک‌ترین نمره را پیدا کند و سپس نام و نمره هر کدام را چاپ کند.
  6. ۶
    متدی به نام sortDescending(String[] names, double[] scores) بنویسید که نمرات را از بزرگ به کوچک مرتب کند. برای هر جابه‌جایی نمره، نام متناظر را هم در همان اندیس جابه‌جا کنید تا هماهنگی حفظ شود. یک روش ساده: پیدا کردن بزرگ‌ترین مقدار در هر دور و جابه‌جایی با جایگاه فعلی.
  7. ۷
    در main، متدها را به ترتیب صدا بزنید و خروجی‌ها را با پیام‌های مناسب چاپ کنید.
اشتباهات رایج و خطاهای احتمالی
  • فراموش کردن هماهنگی نام و نمره: هنگام مرتب‌سازی، فقط نمرات را جابه‌جا کنید و نام‌ها را نه، نتیجه این می‌شود که بعد از مرتب‌سازی، نام‌ها با نمرات هماهنگ نیستند. باید هر جابه‌جایی نمره، نام متناظر را هم جابه‌جا کند.
  • مقدار اولیه اشتباه برای ماکس و مین: برای پیدا کردن بزرگ‌ترین نمره، از scores[0] شروع کنید، نه صفر. اگر همه نمرات مثبت باشند مشکلی پیش نمی‌آید، اما برای حالت‌های مرزی درست نیست.
  • تقسیم صحیح در میانگین: اگر بنویسید sum / scores.length و هر دو از نوع int باشند، نتیجه اعشاری نخواهد بود. حتماً یکی را به double تبدیل کنید.
  • استفاده از nextInt بعد از nextLine یا برعکس: بعد از دریافت نام با nextLine، اگر می‌خواهید نمره بگیرید با nextDouble مشکلی نیست. اما اگر ترتیب برعکس باشد، باید یک nextLine اضافه در وسط بگذارید تا Enter باقی‌مانده پاک شود.
  • خطای اندیس در حلقه مرتب‌سازی: در حلقه‌های مرتب‌سازی، مرزها را با دقت بنویسید. اندیس داخلی نباید از طول آرایه بیشتر شود. از < استفاده کنید، نه <=.

بررسی رشته پالیندروم

برنامه‌ای بنویسید که یک رشته از کاربر دریافت کند و بررسی کند آیا آن رشته پالیندروم (آینه‌ای) است یا نه. پالیندروم یعنی از دو طرف که بخوانید یکسان باشد؛ مثل radar یا level.

راهنمای گام‌به‌گام
  1. ۱
    رشته را با Scanner و nextLine() بگیرید تا فاصله‌ها هم اگر بود دریافت شوند.
  2. ۲
    رشته را با toLowerCase() به حروف کوچک تبدیل کنید تا مقایسه به بزرگی و کوچکی حساس نباشد. نتیجه را در یک متغیر جدید ذخیره کنید.
  3. ۳
    دو اندیس در نظر بگیرید: یکی از ابتدا (0) و یکی از انتها (length() - 1).
  4. ۴
    با یک حلقه while، تا وقتی اندیس چپ کوچک‌تر از راست است، کاراکترهای متناظر را با charAt مقایسه کنید. اگر جایی تفاوت دیدید، یعنی پالیندروم نیست و باید از حلقه خارج شوید.
  5. ۵
    در هر دور، اندیس چپ یکی زیاد و اندیس راست یکی کم می‌شود.
  6. ۶
    بعد از حلقه، بر اساس نتیجه پیام مناسب چاپ کنید.
اشتباهات رایج و خطاهای احتمالی
  • مقایسه با == به‌جای equals: اگر رشته‌ها را با == مقایسه کنید، ممکن است نتیجه غلط بگیرید. برای مقایسه محتوای رشته همیشه از equals یا equalsIgnoreCase استفاده کنید.
  • عدم تبدیل به حروف کوچک: اگر رشته را به حروف کوچک تبدیل نکنید، «Radar» پالیندروم تشخیص داده نمی‌شود، چون «R» با «r» برابر نیست.
  • شرط حلقه اشتباه: باید تا وقتی اندیس چپ کوچک‌تر است ادامه دهید. اگر <= بنویسید، وسط رشته یک مقایسه اضافه انجام می‌شود که اشکالی ندارد، اما بهتر است < باشد.
  • فراموش کردن حالت خالی: اگر رشته خالی باشد، length() صفر است و حلقه اصلاً اجرا نمی‌شود. رشته خالی معمولاً پالیندروم در نظر گرفته می‌شود، اما بهتر است با یک پیام روشن به کاربر اعلام شود.
  • مقایسه فاصله‌ها: اگر رشته حاوی فاصله باشد، ممکن است پالیندروم تشخیص داده نشود. برای تمرین‌های اولیه، ورودی را بدون فاصله فرض کنید.

ضرب دو ماتریس ۳×۳

برنامه‌ای بنویسید که دو ماتریس ۳×۳ (آرایه دوبعدی) را از کاربر دریافت کند و حاصل‌ضرب آن‌ها را محاسبه و چاپ کند. ماتریس حاصل هم ۳×۳ است.

راهنمای گام‌به‌گام
  1. ۱
    دو آرایه دوبعدی int[3][3] تعریف کنید: یکی برای ماتریس اول، یکی برای دوم.
  2. ۲
    با دو حلقه تودرتو، مقادیر هر دو ماتریس را از کاربر بگیرید. برای هر خانه، شماره سطر و ستون را از کاربر بپرسید تا بداند کجاست.
  3. ۳
    یک آرایه سوم int[3][3] برای نتیجه بسازید. جاوا آن را به‌طور خودکار با صفر پر می‌کند.
  4. ۴
    برای محاسبه هر خانه از حاصل‌ضرب، به سه حلقه تودرتو نیاز دارید: یک حلقه بیرونی روی سطرهای نتیجه، یک حلقه وسط روی ستون‌های نتیجه، و یک حلقه درونی روی اندیس مشترک k.
  5. ۵
    درونی‌ترین حلقه، مقدار هر خانه را این‌طور به‌روزرسانی می‌کند: result[i][j] += a[i][k] * b[k][j];
  6. ۶
    در پایان، ماتریس نتیجه را با دو حلقه تودرتو چاپ کنید.
اشتباهات رایج و خطاهای احتمالی
  • اشتباه در ترتیب اندیس‌ها: در فرمول ضرب ماتریس، a[i][k] و b[k][j] درست است. اگر جای i و j را عوض کنید، نتیجه غلط می‌شود.
  • فراموش کردن مقدار اولیه صفر: خانه‌های آرایه نتیجه باید قبل از جمع با محصولات جدید، صفر باشند. اگر مقدار اولیه دیگری داشته باشند، نتیجه اشتباه می‌شود. خوشبختانه جاوا به‌طور خودکار صفر می‌گذارد.
  • مخلوط کردن اندیس سطر و ستون در چاپ: هنگام چاپ، اول سطر و بعد ستون. یعنی result[i][j] نه result[j][i].
  • تعداد حلقه‌ها: ضرب ماتریس سه حلقه لازم دارد، نه دو. اگر فقط دو حلقه بنویسید، نمی‌توانید محصول را به‌درستی جمع کنید.
  • استفاده از nextLine بعد از nextInt بدون پاک‌سازی: اگر بعد از گرفتن عدد، بخواهید متن بگیرید، باید یک nextLine اضافه بگذارید. اما در این تمرین همه ورودی‌ها عدد هستند، پس این مشکل پیش نمی‌آید.

پرسش و پاسخ

پرسش‌های پرتکرار این هفته و پاسخ روشن آن‌ها

این بخش جمع‌بندی پرسش‌هایی است که معمولاً در هفته چهارم برای دانشجویان پیش می‌آید. اگر پرسشی مشابه داشتید، پاسخ آن را همین‌جا پیدا می‌کنید.

پرسش: تفاوت int[] a = {1, 2, 3}; با int[] a = new int[]{1, 2, 3}; چیست؟

پاسخ: از نظر عملکرد و نتیجه، این دو شکل کاملاً یکسان هستند. هر دو یک آرایه سه‌عضوی می‌سازند و مقادیر ۱، ۲ و ۳ را در آن قرار می‌دهند. تفاوت فقط در شکل نوشتن است. شکل اول برای وقتی است که آرایه را در همان خط اعلان می‌کنید. شکل دوم وقتی مفید است که می‌خواهید آرایه را در یک خط جدید یا در جای دیگری مقداردهی کنید. مثلاً int[] a; a = new int[]{1, 2, 3};. در هر دو حالت، طول آرایه برابر ۳ است.

پرسش: چرا آرایه‌ای که به متد می‌فرستم داخل متد تغییر می‌کند، ولی متغیر ساده این‌طور نیست؟

پاسخ: در جاوا، متغیرهای ساده (مثل int) به‌صورت مقدار (by value) فرستاده می‌شوند. یعنی یک کپی از مقدار گرفته می‌شود و متد با آن کپی کار می‌کند. اما آرایه‌ها از نوع ارجاعی هستند. یعنی وقتی آرایه را می‌فرستید، در واقع آدرس حافظه‌اش فرستاده می‌شود. متد از طریق این آدرس به خود آرایه اصلی دسترسی دارد و هر تغییری در محتوای آن، روی آرایه اصلی هم دیده می‌شود. این نکته برای هر شیء دیگری (مثل StringBuilder) هم صدق می‌کند.

پرسش: چرا وقتی می‌نویسم System.out.println(arr); چیزی شبیه [I@1b6d3586 چاپ می‌شود؟

پاسخ: این خروجی، آدرس حافظه و نوع آرایه است، نه محتوای آن. وقتی آرایه را به println می‌دهید، جاوا متد toString را صدا می‌زند. اما آرایه‌ها نسخه اختصاصی خودشان را از toString ندارند و از نسخه پیش‌فرض Object استفاده می‌کنند که آدرس حافظه را برمی‌گرداند. برای دیدن محتوای واقعی آرایه، همیشه از Arrays.toString(arr) استفاده کنید. این متد آرایه را به شکل خوانا مثل [1, 2, 3] برمی‌گرداند.

پرسش: تفاوت String s = "Java"; با String s = new String("Java"); چیست؟

پاسخ: در حالت اول، جاوا ابتدا به String Pool نگاه می‌کند. اگر رشته‌ای با محتوای "Java" در Pool باشد، همان شیء استفاده می‌شود. اگر نباشد، یک شیء جدید ساخته و در Pool ذخیره می‌شود. در حالت دوم، همیشه یک شیء جدید در Heap بیرون از Pool ساخته می‌شود، حتی اگر رشته‌ای با همان محتوا در Pool وجود داشته باشد. نتیجه عملی این است که دو متغیر ساخته‌شده با literal ممکن است به یک شیء اشاره کنند، ولی یکی که با new ساخته شده به شیء جداگانه. برای مقایسه محتوا فرقی نمی‌کند، اما برای کارایی و مصرف حافظه، استفاده از literal بهتر است.

پرسش: کِی از StringBuilder استفاده کنم و کِی از String؟

پاسخ: قاعده ساده این است: اگر قرار است متن را یک بار بسازید و بعد فقط بخوانید، String انتخاب طبیعی و ساده‌ای است. اما اگر قرار است متن را در حلقه یا در چند مرحله پیوسته تغییر بدهید (مثلاً ساخت خروجی یک گزارش با هزار خط، یا پیوند دادن مکرر رشته در حلقه)، از StringBuilder استفاده کنید. تفاوت در مصرف حافظه و سرعت است. هر تغییر در String یک شیء جدید می‌سازد، اما StringBuilder در همان شیء تغییر می‌دهد. برای مقایسه دو StringBuilder، همیشه اول به String تبدیل کنید و بعد equals بزنید.

پرسش: چرا نتیجه 5 / 2 برابر ۲ است، نه ۲.۵؟

پاسخ: وقتی هر دو طرف تقسیم از نوع صحیح (int، byte، short یا long) باشند، جاوا تقسیم صحیح انجام می‌دهد و بخش اعشاری را حذف می‌کند. این رفتار به این دلیل است که جاوا به نوع عملوندها وفادار می‌ماند. برای گرفتن نتیجه اعشاری، حداقل یکی از طرفین باید double یا float باشد. مثلاً 5.0 / 2 نتیجه 2.5 می‌دهد. اگر هر دو طرف متغیر باشند، می‌توانید یکی را با (double) تبدیل کنید: (double) a / b. توجه کنید که (double) (a / b) نتیجه را عوض نمی‌کند، چون اول تقسیم صحیح انجام می‌شود و بعد نتیجه به double تبدیل می‌شود.

پرسش: چطور بفهمم خطای برنامه‌ام از نوع کامپایل است یا زمان اجرا؟

پاسخ: ساده‌ترین راه این است که ببینید برنامه اصلاً شروع می‌شود یا نه. اگر برنامه شروع نشد و کامپایلر خطا داد، خطای کامپایل است. اگر برنامه شروع شد ولی در وسط کار متوقف شد و پیام خطایی با کلمه Exception نمایش داده شد، خطای زمان اجرا است. برای تمرین، عمداً یک خطای کامپایل (مثلاً جا انداختن یک سمی‌کالن) و یک خطای زمان اجرا (مثلاً دسترسی به اندیس آرایه خارج از محدوده) بسازید و تفاوت را ببینید. این تجربه به شما کمک می‌کند در آینده سریع‌تر دسته خطا را تشخیص دهید.

پرسش: تفاوت Step Over و Step Into چیست و کدام را انتخاب کنم؟

پاسخ: Step Over (F8) خط فعلی را کامل اجرا می‌کند و به خط بعدی می‌رود. اگر خط فعلی فراخوانی یک متد باشد، متد اجرا می‌شود اما بدون توقف داخل آن. Step Into (F7) اگر خط فعلی فراخوانی متد باشد، وارد بدنه آن متد می‌شود و اولین خط متد را نشان می‌دهد. انتخاب بستگی به این دارد که آیا می‌خواهید داخل متد را ببینید یا نه. اگر مطمئن هستید متد درست کار می‌کند، Step Over بزنید. اگر شک دارید یا می‌خواهید منطق متد را بررسی کنید، Step Into بزنید. برای شروع، معمولاً از Step Over استفاده می‌کنید و فقط وقتی به متد مشکوک شدید، Step Into می‌زنید.

پرسش: آیا حتماً باید از IntelliJ IDEA برای Debugger استفاده کنم؟

پاسخ: خیر. اکثر محیط‌های برنامه‌نویسی جاوا (IntelliJ IDEA، Eclipse، NetBeans، VS Code با افزونه) یک Debugger دارند. مفاهیم پایه مثل Breakpoint، Step Over، Step Into و Resume در همه این‌ها مشترک است. فقط نام منوها و کلیدهای میانبر ممکن است کمی متفاوت باشد. اگر IntelliJ IDEA نصب دارید، از آن استفاده کنید. اگر محیط دیگری دارید، همان را استفاده کنید. مهم این است که مفهوم Debugger را درک کنید، نه ابزار خاص.

پرسش: در آرایه دوبعدی، table.length چه چیزی را برمی‌گرداند؟

پاسخ: table.length تعداد سطرها را برمی‌گرداند، نه تعداد کل خانه‌ها. مثلاً در یک آرایه ۳×۴، table.length برابر ۳ است. برای گرفتن تعداد ستون‌های یک سطر خاص، باید از table[row].length استفاده کنید. در آرایه‌های مستطیلی همه سطرها طول یکسان دارند، اما در آرایه‌های دندانه‌دار (jagged) هر سطر می‌تواند طول متفاوتی داشته باشد، پس همیشه بهتر است در حلقه داخلی از table[row].length استفاده کنید. این نکته جلوی خطای ArrayIndexOutOfBoundsException را می‌گیرد.

جمع‌بندی و نکات کلیدی

مرور سریع مطالب این هفته

آرایه‌های یک‌بعدی

  • آرایه مجموعه‌ای از مقادیر هم‌نوع است که با یک نام مدیریت می‌شود.
  • سه مرحله: declaration، allocation با new، initialization.
  • اندیس از صفر شروع می‌شود؛ بزرگ‌ترین اندیس معتبر length - 1 است.
  • مقدار پیش‌فرض خانه‌ها: صفر برای اعداد، false برای boolean، null برای کلاس‌ها.
  • پیمایش با for (برای تغییر یا نیاز به اندیس) یا enhanced for (برای خواندن).
  • متدهای آماده در Arrays: toString، sort، fill، copyOf، equals.
  • خطای ArrayIndexOutOfBoundsException هنگام دسترسی به اندیس نامعتبر رخ می‌دهد.

آرایه‌های دوبعدی

  • آرایه دوبعدی = آرایه‌ای از آرایه‌ها. هر سطر یک آرایه مستقل است.
  • دسترسی: table[row][col] — اول سطر، بعد ستون.
  • تعداد سطرها: table.length. تعداد ستون‌های یک سطر: table[row].length.
  • آرایه دندانه‌دار: سطرهایی با طول متفاوت. ساخت با new int[n][]، سپس ساختن هر سطر جداگانه.
  • سطر ساخته‌نشده مقدار null دارد و خواندن طولش باعث NullPointerException می‌شود.

متدها

  • متد یک بسته کد نام‌دار است که یک کار مشخص انجام می‌دهد.
  • ساختار: نوع بازگشتی، نام، پارامترها، بدنه، در صورت نیاز return.
  • void یعنی چیزی برنمی‌گرداند. برای انواع دیگر، حتماً باید مقدار برگرداند.
  • پارامتر = متغیر در تعریف؛ آرگومان = مقدار در فراخوانی.
  • آرایه با ارجاع به متد فرستاده می‌شود؛ تغییر در متد روی آرایه اصلی اثر می‌گذارد.
  • متغیرهای محلی فقط تا پایان همان متد زنده‌اند (Scope).
  • static اجازه می‌دهد متد را بدون ساختن شیء صدا بزنید.

Overloading و Type Casting

  • Overloading = چند متد با نام یکسان و لیست پارامتر متفاوت (تعداد یا نوع).
  • تفاوت فقط در نام پارامتر یا فقط در نوع بازگشتی، overloading نیست و خطا می‌دهد.
  • Widening (مثل int به double) خودکار انجام می‌شود.
  • Narrowing (مثل double به int) نیاز به cast صریح دارد و ممکن است داده از دست برود.
  • تقسیم دو عدد صحیح، نتیجه صحیح می‌دهد. برای نتیجه اعشاری، حداقل یکی را به double تبدیل کنید.
  • ترتیب cast مهم است: (double) a / b با (double) (a / b) متفاوت است.

رشته‌ها (String)

  • String یک کلاس است، نه نوع اولیه. تغییرناپذیر (immutable).
  • متدهای مهم: length، charAt، substring، indexOf، replace، split، toLowerCase، toUpperCase، trim، strip، isEmpty، isBlank، equals، equalsIgnoreCase، contains، startsWith، endsWith.
  • مقایسه محتوا با equals، نه ==. دام کلاسیک امتحان‌ها.
  • substring(a, b): بازه نیم‌باز، یعنی a شامل، b شامل نیست.
  • indexOf در صورت پیدا نشدن مقدار -1 می‌دهد.
  • خطای StringIndexOutOfBoundsException هنگام دسترسی به اندیس نامعتبر رخ می‌دهد.
  • String Pool: literalها مشترک ذخیره می‌شوند، new String شیء جداگانه می‌سازد.
  • StringBuilder تغییرپذیر است و برای تغییرات زیاد در متن مناسب است.

StringBuilder

  • متدهای مهم: append، insert، delete، replace، reverse، length، charAt، setCharAt، toString.
  • برای مقایسه، اول به String تبدیل کنید و بعد equals بزنید.
  • برای تغییرات زیاد در متن از StringBuilder، برای متن‌های ثابت از String.

عیب‌یابی و Debugger

  • سه دسته خطا: کامپایل (قبل از اجرا)، زمان اجرا (حین اجرا، با Exception)، منطقی (خروجی اشتباه بدون خطا).
  • خطاهای زمان اجرا رایج: ArrayIndexOutOfBoundsException، NullPointerException، ArithmeticException، NumberFormatException، StringIndexOutOfBoundsException.
  • Stack Trace را بخوانید: نوع خطا و شماره خط.
  • Breakpoint: توقف در نقطه دلخواه برای بررسی متغیرها.
  • Step Over (F8): اجرای یک خط و رفتن به خط بعد. Step Into (F7): ورود به متد. Step Out (Shift+F8): خروج از متد. Resume (F9): ادامه تا Breakpoint بعدی.
  • برای خطای منطقی، Debugger بهترین ابزار است.
