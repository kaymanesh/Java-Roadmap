متغیر و ثابت

چطور یک مقدار را در حافظه نگه داریم و بعداً به آن دسترسی داشته باشیم

متغیر چیست؟

فرض کنید می‌خواهید سن یک دانشجو را در برنامه ذخیره کنید. برای این کار به یک ظرف نیاز دارید که بتواند یک عدد را نگه دارد و هر وقت خواستیم، آن را بخوانیم یا عوض کنیم. به این ظرف، متغیر می‌گوییم. متغیر در حافظه اصلی سیستم (RAM) ساخته می‌شود و تا وقتی برنامه در حال اجراست، زنده می‌ماند.

تعریف ساده متغیر یک جعبه برچسب‌دار در حافظه است. برای هر جعبه سه چیز مشخص می‌کنیم: چه نوع داده‌ای در آن قرار می‌گیرد (نوع داده)، با چه نامی صدایش بزنیم (نام متغیر)، و در ابتدا چه مقداری در آن باشد (مقدار اولیه).

ساختار تعریف یک متغیر

در جاوا، تعریف متغیر سه بخش دارد: نوع داده، نام و در صورت نیاز مقدار اولیه.

Java 
int age = 21;              // whole number
double price = 19.99;         // decimal number
char grade = 'A';             // single character
boolean isPassed = true;     // true or false
چرا حتماً باید نوع داده را بنویسیم؟ جاوا یک زبان ایستا نوع‌دار است. یعنی وقتی یک متغیر را از نوع int تعریف کردید، تا آخر همان بلوک کد فقط می‌تواند عدد صحیح بپذیرد. این دقت، جلوی بسیاری از خطاهای پنهان را می‌گیرد و برخلاف زبان‌های پویا مثل Python، اجازه نمی‌دهد یک متغیر در هر لحظه نوعش عوض شود.

تغییر مقدار یک متغیر

بعد از تعریف متغیر، می‌توانید در هر جای برنامه مقدارش را با عملگر = عوض کنید. جاوا همیشه آخرین مقداری که در متغیر گذاشته شده را به یاد می‌آورد.

Java 
int age = 21;
System.out.println(age);   // prints 21

age = 22;                // update the value
System.out.println(age);   // prints 22

ثابت (Constant)

گاهی می‌خواهیم یک مقدار را یک بار تعریف کنیم و مطمئن باشیم تا آخر برنامه دست نمی‌خورد. مثلاً عدد پی یا حداکثر تعداد کاربران مجاز. برای این حالت از کلمه کلیدی final استفاده می‌کنیم. به چنین متغیری، ثابت می‌گوییم.

Java 
final double PI = 3.14159;
final int MAX_USERS = 100;

// PI = 3.14;   // ERROR: cannot reassign a final variable
تفاوت متغیر و ثابت متغیر را می‌توانید هر چند بار که خواستید عوض کنید. ثابت را فقط یک بار، همان موقع تعریف، مقدار می‌دهید. اگر بخواهید بعداً مقدارش را عوض کنید، کامپایلر خطا می‌دهد. این خطا در واقع یک محافظ است تا اشتباهاً مقدار مهمی مثل عدد پی تغییر نکند.
قرارداد نام‌گذاری ثابت‌ها طبق استاندارد جاوا، نام ثابت‌ها را با حروف بزرگ و کلمات جدا شده با زیرخط می‌نویسیم. مثل MAX_USERS، PI یا MIN_AGE. این قرارداد به خواننده کد کمک می‌کند در یک نگاه بفهمد با یک ثابت طرف است، نه یک متغیر معمولی.

انواع داده اولیه

هشت نوع داده‌ای که پایه همه برنامه‌های جاوا هستند

جاوا هشت نوع داده اولیه دارد. این‌ها ساده‌ترین انواع داده هستند و مقدار واقعی را مستقیماً در حافظه نگه می‌دارند. بقیه انواع داده (مثل String یا کلاس‌هایی که بعداً می‌سازید) از نوع ارجاعی هستند و فقط به یک آدرس در حافظه اشاره می‌کنند.

جدول کامل انواع اولیه

نوع داده حجم در حافظه محدوده مقادیر مقدار پیش‌فرض مثال
byte ۱ بایت -128 … 127 0 byte b = 100;
short ۲ بایت -32,768 … 32,767 0 short s = 30000;
int ۴ بایت -2,147,483,648 … 2,147,483,647 0 int i = 100000;
long ۸ بایت حدود ±9.2 × 10¹⁸ 0L long l = 15000000000L;
float ۴ بایت حدود ±3.4 × 10³⁸ 0.0f float f = 3.14f;

دسته‌بندی ساده‌تر

برای راحتی به خاطر سپردن، این هشت نوع را در چهار دسته می‌توان دید:

اعداد صحیح

byte، short، int، long

برای شمردن و مقادیر بدون اعشار.

اعداد اعشاری

float و double

برای مقادیر با اعشار. double دقت بیشتری دارد و پیش‌فرض است.

کاراکتری

char

برای نگه‌داری یک حرف یا نماد، داخل تک‌کوتیشن.

منطقی

boolean

فقط دو مقدار: درست یا غلط. پایه شرط‌ها.

کدام نوع را انتخاب کنیم؟

برای اعداد صحیح، تقریباً همیشه int انتخاب اول است. از byte و short فقط وقتی استفاده می‌کنیم که حافظه محدود باشد (مثل آرایه‌های خیلی بزرگ) و از long برای اعداد خیلی بزرگ (بیشتر از دو میلیارد). برای اعداد اعشاری، به‌طور پیش‌فرض double انتخاب کنید، چون دقت بالاتری دارد.

Java 
int studentAge = 20;
double gpa = 3.75;
char grade = 'A';
boolean isGraduated = false;

long worldPopulation = 8000000000L;   // L at the end
float bodyTemp = 36.6f;                 // f at the end
پسوندهای اجباری برای long باید در انتهای عدد حرف L بنویسید و برای float حرف f. اگر این پسوندها را ننویسید، جاوا عدد اعشاری را به‌طور پیش‌فرض double در نظر می‌گیرد و عدد صحیح بزرگ را int، که در هر دو حالت منجر به خطای کامپایل می‌شود.

سرریز (Overflow)

هر نوع داده، یک ظرفیت مشخص دارد. اگر مقداری بزرگ‌تر از ظرفیت در آن بریزید، مقدارش دور می‌زند و به کوچک‌ترین مقدار همان نوع تبدیل می‌شود. این رفتار ممکن است در ابتدا عجیب به نظر برسد، اما نتیجه یک قاعده مشخص در ریاضیات کامپیوتری است.

Java 
byte b = 127;   // maximum value of byte
b++;            // overflow happens here
System.out.println(b);   // prints -128, not 128
مقدار پیش‌فرض فقط برای فیلدهای کلاس متغیرهایی که داخل متدها (مثل main) تعریف می‌شوند، مقدار پیش‌فرض ندارند و حتماً باید قبل از استفاده به آن‌ها مقدار بدهید. اگر بدون مقداردهی از آن‌ها استفاده کنید، کامپایلر خطا می‌دهد. مقدار پیش‌فرض جدول بالا، فقط برای فیلدهایی است که داخل کلاس تعریف می‌شوند، نه متغیرهای محلی.
۳

نام‌گذاری متغیرها

قوانین و سبک استاندارد نام‌گذاری در جاوا

قوانین اجباری

جاوا برای نام متغیرها چند قاعده سخت‌گیرانه دارد. اگر یکی از این قواعد نقض شود، کامپایلر خطا می‌دهد و برنامه اجرا نمی‌شود.

  • نام متغیر باید با یک حرف، زیرخط (_) یا دلار ($) شروع شود.
  • نمی‌تواند با رقم شروع شود. مثلاً 1name معتبر نیست.
  • نمی‌تواند شامل فاصله باشد. مثلاً my age معتبر نیست.
  • به بزرگی و کوچکی حروف حساس است. age و Age دو متغیر متفاوت هستند.
  • نمی‌تواند یکی از کلمات کلیدی جاوا باشد. کلماتی مثل int، class، for، if رزرو شده‌اند.

سبک استاندارد: Camel Case

جدا از قوانین اجباری، جاوا یک قرارداد سبک هم دارد که همه برنامه‌نویسان حرفه‌ای آن را رعایت می‌کنند. طبق این قرارداد، نام متغیرها و متدها با حرف کوچک شروع می‌شود و حرف اول هر کلمه بعدی با حرف بزرگ نوشته می‌شود. به این سبک، Camel Case می‌گویند.

✅ درست

firstName
studentAge
totalPrice
isLoggedIn

❌ نادرست

first_name (سبک snake_case)
FirstName (سبک PascalCase)
1stName (شروع با رقم)
my age (دارای فاصله)

نام معنادار انتخاب کنید یک متغیر با نام a یا x هیچ چیز درباره محتوایش نمی‌گوید، اما studentAge خودش را توضیح می‌دهد. کد باید خوانده شود، نه فقط اجرا. کسی که شش ماه بعد به کد شما نگاه می‌کند، احتمالاً خودتان هستید؛ نام معنادار، بزرگ‌ترین لطفی است که به خودتان می‌کنید.
حساسیت به حروف بزرگ و کوچک جاوا به بزرگی و کوچکی حروف حساس است. یعنی age، Age و AGE سه متغیر کاملاً متفاوت هستند. این ویژگی در ابتدا ممکن است باعث اشتباه شود، اما یک قاعده ثابت در تمام زبان‌های خانواده C است.

عملگرهای ریاضی

محاسبات پایه و ترتیب اجرای آن‌ها

پنج عملگر اصلی

جاوا پنج عملگر ریاضی دارد که روی متغیرها و مقادیر عمل می‌کنند. این‌ها پایه هر محاسبه‌ای در برنامه‌های واقعی هستند.

عملگر نام توضیح مثال (a=10, b=3) نتیجه
+جمعجمع دو عددa + b13
-تفریقتفاضل دو عددa - b7
*ضربحاصل‌ضربa * b30
/تقسیمخارج‌قسمتa / b3
%باقیماندهباقی‌مانده تقسیمa % b1
Java 
int a = 10, b = 3;

System.out.println(a + b);   // 13
System.out.println(a - b);   // 7
System.out.println(a * b);   // 30
System.out.println(a / b);   // 3  ← integer division!
System.out.println(a % b);   // 1

تله تقسیم صحیح

یکی از رایج‌ترین اشتباهات مبتدیان، انتظار نتیجه اعشاری از تقسیم دو عدد صحیح است. وقتی هر دو طرف تقسیم از نوع int باشند، نتیجه هم int است و بخش اعشاری آن به‌طور کامل حذف می‌شود. یعنی 7 / 2 برابر 3 است، نه 3.5.

تقسیم صحیح بخش اعشاری را حذف می‌کند برای گرفتن نتیجه دقیق اعشاری، حداقل یکی از طرفین تقسیم باید double یا float باشد. مثلاً 7.0 / 2 نتیجه 3.5 می‌دهد، اما 7 / 2 نتیجه 3.
Java 
System.out.println(7 / 2);         // 3   (both int)
System.out.println(7 / 2.0);       // 3.5 (one is double)
System.out.println(7.0 / 2);       // 3.5
System.out.println((double) 7 / 2);   // 3.5 (cast)

ترتیب اجرا (اولویت عملگرها)

وقتی چند عملگر در یک عبارت کنار هم قرار می‌گیرند، جاوا به ترتیب اولویت آن‌ها را اجرا می‌کند. این ترتیب، همان ترتیبی است که در ریاضیات مدرسه یاد گرفته‌اید.

  1. ۱
    پرانتز: ابتدا هر چیزی که داخل پرانتز است محاسبه می‌شود.
  2. ۲
    عملگرهای یکانی: مثل ++ و --.
  3. ۳
    ضرب، تقسیم و باقیمانده: از چپ به راست.
  4. ۴
    جمع و تفریق: از چپ به راست.
  5. ۵
    انتساب: عملگر = در آخر اجرا می‌شود.
Java 
int r1 = 2 + 3 * 4;        // 14 (multiplication first)
int r2 = (2 + 3) * 4;      // 20 (parentheses first)
int r3 = 10 - 4 / 2;       // 8
int r4 = (10 - 4) / 2;     // 3
پرانتز، همیشه پرانتز حتی وقتی اولویت‌ها را خوب می‌دانید، برای خوانایی بهتر از پرانتز استفاده کنید. (a + b) / 2 بسیار خواناتر از a + b / 2 است. کد برای خواندن نوشته می‌شود، نه فقط برای اجرا.
۵

عملگرهای مقایسه‌ای و منطقی

پایه ساخت شرط‌ها و تصمیم‌گیری در برنامه

عملگرهای مقایسه‌ای

این عملگرها دو مقدار را با هم مقایسه می‌کنند و همیشه یک نتیجه boolean برمی‌گردانند؛ یعنی یا true یا false. خروجی این عملگرها، پایه ساخت شرط‌هایی است که در هفته‌های بعد یاد می‌گیریم.

عملگر معنی مثال (x=5, y=8) نتیجه
==مساوی است باx == yfalse
!=مساوی نیست باx != ytrue
>بزرگ‌تر ازx > yfalse
<کوچک‌تر ازx < ytrue
>=بزرگ‌تر یا مساویx >= yfalse
<=کوچک‌تر یا مساویx <= ytrue
اشتباه رایج: = با == فرق دارد = یک عملگر انتساب است و مقدار را در متغیر می‌گذارد. == عملگر مقایسه است و دو مقدار را با هم می‌سنجد. اگر در یک شرط به‌جای == از = استفاده کنید، خطای کامپایل می‌گیرید. همیشه به خاطر بسپارید: = برای انتساب، == برای مقایسه.

عملگرهای منطقی

برای ترکیب چند شرط با هم، از عملگرهای منطقی استفاده می‌کنیم. این عملگرها روی مقادیر boolean کار می‌کنند و خروجی‌شان هم boolean است.

عملگر نام قانون مثال
&& AND (و) هر دو شرط باید درست باشند true && false → false
|| OR (یا) حداقل یکی درست باشد کافی است true || false → true
! NOT (نقیض) مقدار را برعکس می‌کند !true → false
Java 
int age = 20;
boolean hasIdCard = true;

boolean canEnter = (age >= 18) && hasIdCard;
System.out.println(canEnter);   // true

boolean isWeekend = false;
boolean isHoliday = true;
System.out.println(isWeekend || isHoliday);   // true

System.out.println(!hasIdCard);               // false

ویژگی Short-Circuit

وقتی از && استفاده می‌کنید و طرف اول false باشد، جاوا طرف دوم را حتی بررسی نمی‌کند. چون در AND، اگر یکی false باشد، نتیجه کل عبارت هم false است. همین رفتار در || هم وجود دارد: اگر طرف اول true باشد، طرف دوم بررسی نمی‌شود.

چرا Short-Circuit مهم است؟ این ویژگی هم سرعت اجرا را بالا می‌برد و هم از خطا جلوگیری می‌کند. مثلاً اگر شرط دوم به متغیری نیاز داشته باشد که فقط وقتی شرط اول درست است وجود دارد، Short-Circuit جلوی خطا را می‌گیرد. این رفتار را در هفته سوم، هنگام ساخت شرط‌های مرکب، بهتر می‌بینید.

ترتیب اولویت

وقتی چند عملگر در یک عبارت با هم هستند، ترتیب اجرا از بیشترین اولویت به کمترین است: اول پرانتز، بعد نقیض !، بعد عملگرهای مقایسه‌ای، بعد &&، بعد ||. برای خوانایی بهتر، حتی وقتی اولویت‌ها را می‌دانید از پرانتز استفاده کنید.

دریافت ورودی با Scanner

تعامل با کاربر و خواندن داده‌ها از صفحه‌کلید

تا اینجا برنامه‌های ما فقط خروجی می‌دادند. اما برنامه‌های واقعی معمولاً از کاربر ورودی می‌گیرند و بر اساس آن تصمیم می‌گیرند. برای خواندن ورودی از صفحه‌کلید در جاوا، از کلاس Scanner استفاده می‌کنیم. این کلاس در پکیج java.util قرار دارد.

سه گام برای استفاده از Scanner

  1. ۱
    در ابتدای فایل، کلاس Scanner را با import java.util.Scanner; وارد کنید.
  2. ۲
    یک شیء از Scanner بسازید که به System.in (ورودی سیستم) وصل باشد.
  3. ۳
    با متد مناسب (مثل nextInt یا nextLine) داده مورد نظر را بخوانید.
Java 
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter your name: ");
        String name = sc.nextLine();

        System.out.print("Enter your age: ");
        int age = sc.nextInt();

        System.out.print("Enter your height: ");
        double height = sc.nextDouble();

        System.out.println("Hello, " + name + "!");
        System.out.println("Age: " + age + ", Height: " + height);

        sc.close();
    }
}

تله معروف: تداخل nextInt و nextLine

یکی از رایج‌ترین مشکلاتی که مبتدیان با آن روبه‌رو می‌شوند، این است که بعد از nextInt یا nextDouble، اگر بلافاصله nextLine صدا بزنید، برنامه به‌جای خواندن متن کاربر، یک رشته خالی برمی‌گرداند. این رفتار باعث می‌شود برنامه، بخش دریافت متن را رد کند و به سراغ خط بعدی برود.

ریشه مشکل وقتی کاربر یک عدد را وارد می‌کند و Enter می‌زند، در واقع دو چیز به برنامه می‌رسد: خود عدد و کاراکتر Enter. متد nextInt عدد را می‌خواند، اما کاراکتر Enter را در بافر ورودی باقی می‌گذارد. حالا اگر nextLine صدا بزنید، همان Enter باقی‌مانده را می‌خواند و یک رشته خالی برمی‌گرداند.
Java — مشکل 
System.out.print("Age: ");
int age = sc.nextInt();        // user types 20 and presses Enter

System.out.print("Name: ");
String name = sc.nextLine();   // BUG: reads the leftover Enter, not the name
Java — راه‌حل 
System.out.print("Age: ");
int age = sc.nextInt();
sc.nextLine();                 // consume the leftover newline

System.out.print("Name: ");
String name = sc.nextLine();   // now works correctly
قاعده ساده هر زمان که بعد از یک متد عددی (nextInt، nextDouble، nextFloat و…) می‌خواهید nextLine صدا بزنید، یک nextLine() اضافه در وسط قرار دهید تا Enter باقی‌مانده پاک شود. اگر بعد از متد عددی از nextInt یا nextDouble دوباره استفاده می‌کنید، نیازی به این کار نیست چون متد عددی، فاصله‌ها و Enter را خودش نادیده می‌گیرد.

بستن Scanner

در انتهای برنامه، متد sc.close() را صدا بزنید. این کار منابع سیستمی را آزاد می‌کند. اما دقت کنید اگر System.in را ببندید، دیگر نمی‌توانید در همان برنامه دوباره از آن بخوانید. برای برنامه‌های کوچک، این کار اهمیت زیادی ندارد، اما عادت خوبی است که بعداً در پروژه‌های بزرگ‌تر به کارتان می‌آید.

تفاوت next و nextLine next() فقط تا اولین فاصله، تب یا Enter می‌خواند. اگر ورودی "Ali Reza" باشد، فقط "Ali" را برمی‌گرداند. nextLine() تا انتهای خط را می‌خواند، پس کل "Ali Reza" را برمی‌گرداند. برای دریافت نام کامل، از nextLine استفاده کنید.

مبدل دما

برنامه‌ای بنویسید که دمای هوا را بر حسب سانتی‌گراد از کاربر دریافت کند و آن را به فارنهایت و کلوین تبدیل کرده و نمایش دهد. چون دما می‌تواند اعشاری باشد، از nextDouble استفاده کنید. خروجی را با دو رقم اعشار نمایش دهید.

فرمول‌ها
  1. فارنهایت = سانتی‌گراد × ۹ ÷ ۵ + ۳۲
  2. کلوین = سانتی‌گراد + ۲۷۳٫۱۵
راهنمای گام‌به‌گام
  1. ۱
    کلاس Scanner را import کنید و یک شیء از آن بسازید.
  2. ۲
    از کاربر دمای سانتی‌گراد را با nextDouble بگیرید و در متغیری از نوع double ذخیره کنید.
  3. ۳
    دو متغیر دیگر برای فارنهایت و کلوین تعریف کنید و با فرمول‌های بالا مقدار بدهید.
  4. ۴
    برای نمایش با دو رقم اعشار، از System.out.printf استفاده کنید. برای عدد اعشاری با دو رقم، از %.2f و برای خط جدید از %n.
  5. ۵
    در پایان، sc.close() را صدا بزنید.
اشتباهات رایج و خطاهای احتمالی
  • استفاده از nextInt به‌جای nextDouble: اگر کاربر دمای ۳۶٫۶ را وارد کند، برنامه خطای ورودی می‌دهد. برای مقادیر اعشاری، همیشه nextDouble.
  • تقسیم صحیح در فرمول: اگر همه اعداد را int بگیرید، 9 / 5 نتیجه 1 می‌شود، نه 1.8. برای اطمینان، در فرمول فارنهایت از 9.0 یا 5.0 استفاده کنید، یا مطمئن شوید متغیر سانتی‌گراد از نوع double است.
  • جا افتادن پرانتز در فرمول: عبارت celsius * 9 / 5 + 32 درست است، اما celsius * 9 / (5 + 32) نتیجه اشتباه می‌دهد. اولویت عملگرها را در فرمول دقیق رعایت کنید.
  • فراموش کردن %n در printf: اگر %n را نگذارید، خروجی‌های متعدد در یک خط به هم می‌چسبند.
  • خطای ورودی در scanf: اگر کاربر به‌جای عدد، حرف وارد کند، برنامه با خطای ورودی متوقف می‌شود. فعلاً نگران این حالت نباشید؛ در هفته‌های بعد یاد می‌گیرید چطور این خطاها را مدیریت کنید.

تبدیل ثانیه به ساعت، دقیقه و ثانیه

برنامه‌ای بنویسید که یک عدد صحیح به‌عنوان تعداد ثانیه از کاربر دریافت کند و آن را به قالب استاندارد ساعت، دقیقه و ثانیه تبدیل کند. مثلاً ورودی ۳۷۲۵ باید به شکل 01:02:05 نمایش داده شود.

منطق تقسیم
  1. تعداد ساعت‌های کامل = کل ثانیه ÷ ۳۶۰۰ (تقسیم صحیح).
  2. باقیمانده بعد از ساعت = کل ثانیه % ۳۶۰۰.
  3. تعداد دقیقه‌های کامل = آن باقیمانده ÷ ۶۰.
  4. تعداد ثانیه‌های باقیمانده = کل ثانیه % ۶۰.
راهنمای گام‌به‌گام
  1. ۱
    یک شیء Scanner بسازید و کل ثانیه را با nextInt در متغیری از نوع int ذخیره کنید.
  2. ۲
    سه متغیر از نوع int تعریف کنید: یکی برای ساعت، یکی برای دقیقه و یکی برای ثانیه.
  3. ۳
    ساعت را با total / 3600 محاسبه کنید. چون هر دو عدد صحیح هستند، بخش اعشاری حذف می‌شود و همان تعداد ساعت کامل به دست می‌آید.
  4. ۴
    دقیقه را با (total % 3600) / 60 محاسبه کنید. اول باقیمانده بعد از ساعت‌ها را جدا می‌کنید و بعد آن را بر ۶۰ تقسیم می‌کنید.
  5. ۵
    ثانیه را با total % 60 محاسبه کنید.
  6. ۶
    برای نمایش دو رقمی (مثلاً 01 به‌جای 1) از printf با قالب %02d:%02d:%02d%n استفاده کنید. عدد ۲ در %02d یعنی حداقل دو رقم و صفر یعنی در صورت نیاز با صفر پر شود.
  7. ۷
    در پایان، sc.close() را صدا بزنید.
اشتباهات رایج و خطاهای احتمالی
  • محاسبه دقیقه به‌روش اشتباه: اگر دقیقه را با (total / 60) % 60 حساب کنید، وقتی total برابر ۳۷۲۵ باشد، باز هم نتیجه درست می‌گیرید. اما روش (total % 3600) / 60 شفاف‌تر است و مستقیماً همان باقیمانده بعد از ساعت‌ها را بر ۶۰ تقسیم می‌کند.
  • استفاده از nextDouble به‌جای nextInt: ثانیه همیشه عدد صحیح است. اگر از nextDouble استفاده کنید، ممکن است محاسباتتان با اعداد اعشاری پیچیده شود.
  • فراموش کردن صفر پیشرو: بدون %02d، خروجی برای ۳۷۲۵ به‌شکل 1:2:5 نمایش داده می‌شود که خوانا نیست.
  • استفاده از %d به‌جای %02d: بدون عدد ۲، عرض ثابت اعمال نمی‌شود و صفر پیشرو اضافه نمی‌شود.
  • خطای تقسیم صحیح در محاسبه ثانیه: اگر ثانیه را با (total % 3600) % 60 حساب کنید، باز هم درست است؛ اما ساده‌ترین شکل total % 60 است.

محاسبه شاخص توده بدنی (BMI)

برنامه‌ای بنویسید که وزن (کیلوگرم) و قد (متر) را از کاربر دریافت کند و شاخص توده بدنی را محاسبه و با دو رقم اعشار نمایش دهد. فرمول محاسبه: BMI = weight / (height × height)

راهنمای گام‌به‌گام
  1. ۱
    یک شیء Scanner بسازید.
  2. ۲
    وزن را با nextDouble در متغیری از نوع double ذخیره کنید.
  3. ۳
    قد را هم با nextDouble در متغیری از نوع double ذخیره کنید.
  4. ۴
    قد را در خودش ضرب کنید (قد به توان دو) و نتیجه را در یک متغیر موقت نگه دارید، یا مستقیماً در فرمول بگذارید.
  5. ۵
    وزن را بر آن مقدار تقسیم کنید و نتیجه را در متغیری به نام bmi نگه دارید.
  6. ۶
    با System.out.printf و قالب %.2f نتیجه را با دو رقم اعشار چاپ کنید.
  7. ۷
    در پایان، sc.close() را صدا بزنید.
اشتباهات رایج و خطاهای احتمالی
  • استفاده از int برای وزن و قد: اگر وزن ۷۰٫۵ باشد، با int خطای ورودی می‌گیرید. همیشه برای این مقادیر از double استفاده کنید.
  • فراموش کردن پرانتز در مخرج: نوشتن weight / height * height غلط است، چون از چپ به راست حساب می‌شود و نتیجه می‌شود (weight / height) × height. حتماً weight / (height * height) بنویسید.
  • اعشار جدا شده با کاما در ورودی: در جاوا، اعداد اعشاری باید با نقطه وارد شوند، نه کاما. اگر کاربر عادت دارد 1,75 بنویسد، برنامه خطا می‌دهد. در هفته‌های بعد یاد می‌گیرید چطور این حالت را هم مدیریت کنید.
  • فراموش کردن واحد در پیام خروجی: پیام پایانی بهتر است واحد را هم نشان دهد، مثلاً «شاخص توده بدنی: ۲۲٫۸۶». این جزو کیفیت کد است.

جابه‌جایی دو عدد بدون متغیر کمکی

دو متغیر عددی از کاربر دریافت کنید و مقادیر آن‌ها را بدون استفاده از متغیر سوم، با هم جابه‌جا کنید. سپس مقادیر جدید را چاپ کنید. برای این کار، از عملگرهای ریاضی (جمع و تفریق) استفاده کنید.

راهنمای گام‌به‌گام
  1. ۱
    دو متغیر a و b از نوع int تعریف کنید و مقادیرشان را با nextInt از کاربر بگیرید.
  2. ۲
    قبل از جابه‌جایی، مقادیر اولیه را چاپ کنید تا بعداً بتوانید مقایسه کنید.
  3. ۳
    در a مجموع دو عدد را بریزید: a = a + b. حالا a مجموع را نگه می‌دارد.
  4. ۴
    در b مقدار اصلی a را بازیابی کنید: b = a - b. حالا b مقدار قبلی a را دارد.
  5. ۵
    در a مقدار اصلی b را بازیابی کنید: a = a - b. حالا a مقدار قبلی b را دارد.
  6. ۶
    مقادیر جدید را چاپ کنید تا جابه‌جایی را ببینید.
اشتباهات رایج و خطاهای احتمالی
  • اشتباه در ترتیب مراحل: ترتیب دقیقاً باید a = a + b، بعد b = a - b و در نهایت a = a - b باشد. اگر جای مراحل را عوض کنید، مقادیر بازیابی نمی‌شوند.
  • خطر سرریز در مقادیر بزرگ: اگر دو عدد خیلی بزرگ باشند، جمعشان ممکن است از ظرفیت int بیشتر شود و سرریز رخ دهد. برای اعداد خیلی بزرگ، این روش امن نیست. اما برای مقادیر معمولی کار می‌کند.
  • فراموش کردن صفر یا اعداد منفی: این روش برای اعداد منفی و صفر هم کار می‌کند. با اعداد نمونه مثل a=5 و b=10 و a=-3 و b=7 تست کنید تا مطمئن شوید.
  • نبودن پیام واضح در خروجی: مقادیر جدید را با پیام روشن چاپ کنید، مثلاً «پس از جابه‌جایی: a = ...، b = ...». این کار تشخیص درست بودن نتیجه را ساده می‌کند.
  • انتظار غیرواقعی از خروجی: اگر مقادیر را با println خیلی ساده چاپ کنید، ممکن است نتوانید تشخیص دهید کدام مقدار مربوط به کدام متغیر است. از برچسب استفاده کنید.

پرسش و پاسخ

پرسش‌های پرتکرار این هفته و پاسخ روشن آن‌ها

این بخش جمع‌بندی پرسش‌هایی است که معمولاً در هفته دوم برای دانشجویان پیش می‌آید. اگر پرسشی مشابه داشتید، پاسخ آن را همین‌جا پیدا می‌کنید.

پرسش: چرا باید نوع داده را دقیق انتخاب کنم؟ نمی‌شود همیشه از int و double استفاده کرد؟

پاسخ: در بسیاری از برنامه‌های کوچک، بله، می‌توانید همیشه از int و double استفاده کنید و کارتان راه بیفتد. اما وقتی برنامه‌های بزرگ‌تر و آرایه‌های خیلی بزرگ می‌سازید، تفاوت حافظه اهمیت پیدا می‌کند. مثلاً اگر یک آرایه با یک میلیون عضو از نوع int داشته باشید، حدود ۴ مگابایت حافظه مصرف می‌شود، اما همان آرایه از نوع byte فقط ۱ مگابایت می‌گیرد. با انتخاب درست نوع داده، هم حافظه کمتری مصرف می‌شود و هم برنامه سریع‌تر اجرا می‌شود. همچنین انتخاب نوع درست، خودش نوعی مستندسازی است: وقتی کسی byte age می‌بیند، می‌فهمد این مقدار نباید بزرگ‌تر از ۱۲۷ باشد.

پرسش: تفاوت float و double در چیست و کدام را انتخاب کنم؟

پاسخ: double دقت بالاتری دارد و ۸ بایت فضا می‌گیرد، در حالی که float ۴ بایت فضا می‌گیرد و دقت کمتری دارد. در عمل، تقریباً همیشه double انتخاب می‌شود، مگر اینکه با حجم عظیمی از داده‌های اعشاری کار کنید و بخواهید در حافظه صرفه‌جویی کنید. حتی در مواردی مثل محاسبه BMI یا مبدل دما، دقت بالای double به کارتان می‌آید. تنها نکته‌ای که باید یادتان باشد این است که برای تعریف یک متغیر float، باید در انتهای عدد حرف f بنویسید؛ مثل 3.14f. برای double نیازی به پسوند نیست.

پرسش: چرا 5 / 2 نتیجه 2.5 نمی‌دهد، بلکه 2 برمی‌گرداند؟

پاسخ: در جاوا، وقتی هر دو طرف تقسیم از یک نوع صحیح باشند (مثل int، byte، short یا long)، نتیجه هم از همان نوع صحیح است و بخش اعشاری آن حذف می‌شود، نه گرد. یعنی 5 / 2 برابر 2 است و 7 / 3 برابر 2. این رفتار به این دلیل است که جاوا به نوع داده عملوندها وفادار می‌ماند. برای گرفتن نتیجه دقیق، حداقل یکی از طرفین باید double یا float باشد. مثلاً 5.0 / 2 یا 5 / 2.0 نتیجه 2.5 می‌دهد. اگر هر دو طرف متغیر باشند، می‌توانید یکی را با (double) تبدیل کنید: (double) a / b.

پرسش: تفاوت = و == دقیقاً چیست؟

پاسخ: = یک عملگر انتساب است. یعنی مقدار سمت راست را در متغیر سمت چپ می‌ریزد. مثلاً age = 20 یعنی در متغیر age مقدار ۲۰ را قرار بده. == یک عملگر مقایسه است و دو مقدار را با هم می‌سنجد. نتیجه‌اش یک boolean است: اگر برابر باشند true، وگرنه false. مثلاً age == 20 اگر age برابر ۲۰ باشد true برمی‌گرداند. اگر در یک شرط، به‌جای == از = استفاده کنید، کامپایلر خطا می‌دهد چون نتیجه انتساب از نوع متغیر است، نه از نوع boolean. همیشه به خاطر بسپارید: = برای گذاشتن مقدار، == برای مقایسه.

پرسش: چرا بعد از nextInt، nextLine رشته خالی برمی‌گرداند؟

پاسخ: وقتی کاربر یک عدد را وارد می‌کند و Enter می‌زند، در واقع دو چیز به برنامه می‌رسد: خود عدد و کاراکتر Enter. متد nextInt عدد را می‌خواند و به برنامه برمی‌گرداند، اما کاراکتر Enter را مصرف نمی‌کند و در بافر ورودی باقی می‌گذارد. حالا اگر بلافاصله nextLine صدا بزنید، این متد به بافر نگاه می‌کند و اولین چیزی که می‌بیند، همان Enter باقی‌مانده است. بنابراین یک رشته خالی برمی‌گرداند و بلافاصله تمام می‌شود. راه‌حل ساده این است که بعد از nextInt، یک nextLine() اضافه صدا بزنید تا آن Enter باقی‌مانده مصرف شود. بعد از آن، nextLine بعدی منتظر ورودی واقعی می‌ماند و متن کاربر را درست می‌خواند.

پرسش: اگر بخواهم نام و نام خانوادگی را با هم از کاربر بگیرم، از next استفاده کنم یا nextLine؟

پاسخ: برای گرفتن نام کامل، از nextLine استفاده کنید. متد next فقط تا اولین فاصله می‌خواند، یعنی اگر کاربر بنویسد «علی رضایی»، فقط «علی» را می‌گیرد و «رضایی» در بافر باقی می‌ماند. متد nextLine تا Enter را می‌خواند و کل «علی رضایی» را برمی‌گرداند. تنها نکته این است که اگر قبل از nextLine از nextInt یا nextDouble استفاده کرده باشید، باید یک nextLine() اضافه در وسط صدا بزنید تا Enter باقی‌مانده پاک شود.

پرسش: چرا مقدار پیش‌فرض برای متغیرهای محلی وجود ندارد؟

پاسخ: متغیرهایی که داخل متدها تعریف می‌شوند، توسط کامپایلر مقدار پیش‌فرض نمی‌گیرند. این یکی از تصمیم‌های طراحی جاواست تا برنامه‌نویس را مجبور کند آگاهانه به متغیر مقدار بدهد. اگر متغیری مقدار پیش‌فرض داشته باشد، ممکن است به‌اشتباه از آن استفاده کنید و یک باگ پنهان در برنامه ایجاد شود. مثلاً اگر متغیر sum به‌طور خودکار صفر باشد، ممکن است فراموش کنید آن را مقداردهی کنید و برنامه ظاهراً درست کار کند، ولی در واقع نتیجه اشتباه بدهد. با اجبار به مقداردهی صریح، این نوع باگ‌ها زودتر کشف می‌شوند. فقط فیلدهای کلاس مقدار پیش‌فرض دارند، چون همیشه با ساختن شیء مقداردهی می‌شوند.

پرسش: آیا می‌توانم نام متغیر را فارسی بنویسم؟

پاسخ: از نظر فنی، جاوا اجازه می‌دهد از حروف یونیکد (که حروف فارسی هم شاملش می‌شود) در نام متغیر استفاده کنید. اما در عمل، این کار توصیه نمی‌شود. سه دلیل اصلی: اول اینکه بسیاری از ابزارهای برنامه‌نویسی، ویرایشگرها و مستندسازها ممکن است در نمایش درست این نام‌ها مشکل داشته باشند. دوم اینکه کد شما ممکن است در پروژه‌های بین‌المللی یا با همکارانی که فارسی نمی‌دانند، قابل خواندن نباشد. سوم اینکه قرارداد استاندارد جامعه جاوا، استفاده از حروف انگلیسی برای نام‌گذاری است. بهتر است نام متغیرها را انگلیسی و معنادار بنویسید و اگر نیاز به توضیح فارسی دارید، در قالب کامنت اضافه کنید.

جمع‌بندی و نکات کلیدی

مرور سریع مطالب این هفته

متغیر و ثابت

  • متغیر یک جعبه برچسب‌دار در حافظه است که سه بخش دارد: نوع داده، نام و مقدار.
  • برای تعریف ثابت، از final استفاده کنید. مقدار ثابت بعد از تعریف قابل تغییر نیست.
  • نام ثابت‌ها را با حروف بزرگ و کلمات جدا شده با زیرخط می‌نویسیم؛ مثل MAX_USERS.

انواع داده اولیه

  • هشت نوع اولیه: byte، short، int، long، float، double، char و boolean.
  • برای اعداد صحیح، پیش‌فرض int؛ برای اعداد اعشاری، پیش‌فرض double.
  • برای long پسوند L و برای float پسوند f الزامی است.
  • مقدار پیش‌فرض فقط برای فیلدهای کلاس وجود دارد، نه متغیرهای محلی.
  • سرریز باعث می‌شود مقدار از ظرفیت نوع داده عبور کند و دور بزند.

نام‌گذاری متغیرها

  • شروع با حرف، زیرخط یا دلار؛ هرگز با رقم.
  • بدون فاصله، بدون کاراکترهای ویژه.
  • حساس به بزرگی و کوچکی حروف.
  • سبک استاندارد: Camel Case؛ مثل studentAge.

عملگرهای ریاضی

  • پنج عملگر اصلی: +، -، *، / و %.
  • تقسیم دو عدد صحیح، نتیجه صحیح می‌دهد و بخش اعشاری را حذف می‌کند.
  • ترتیب اجرا: پرانتز، بعد ضرب و تقسیم و باقیمانده، بعد جمع و تفریق.
  • برای خوانایی بهتر، حتی وقتی اولویت‌ها را می‌دانید از پرانتز استفاده کنید.

عملگرهای مقایسه‌ای و منطقی

  • عملگرهای مقایسه‌ای همیشه یک boolean برمی‌گردانند.
  • = انتساب، == مقایسه. اشتباه گرفتن این دو، خطای رایج مبتدیان است.
  • عملگرهای منطقی: && (و)، || (یا) و ! (نقیض).
  • Short-Circuit: در && اگر طرف اول false باشد، طرف دوم بررسی نمی‌شود.

Scanner

  • سه گام: import، ساخت شیء با new Scanner(System.in) و خواندن با متد مناسب.
  • متدهای پرکاربرد: nextInt، nextDouble، nextBoolean، next و nextLine.
  • بعد از nextInt قبل از nextLine، یک nextLine() اضافه بزنید.
  • در پایان برنامه، sc.close() را صدا بزنید.
